# A股选股-估值-量价操作流程

## 0. 任务路由（agent 入口）

收到"按照本流程执行/分析…"类指令时，先在此表定位模块，再按对应章节的执行规则与脚本操作。**术语消歧**："值得关注的公司"是阶段一的 `worth_attention`（公司质量结论）；"今日值得关注的股票/走势"指每日扫描的**买入候选**（§8）。含"今日/走势/盘面/买点"的指令默认路由到 §8；"发起当日的每日扫描"类整体指令路由到 §9.1 组合流程（先持仓、后池）。

| 指令类型（示例） | 模块 | 脚本（确定性部分） | 主要输入 → 输出 | 大模型职责 |
| --- | --- | --- | --- | --- |
| 发起当日的每日扫描（持仓健康度 + 池内关注对象，支持盘中发起） | §9.1 组合流程 | `scan_holdings_sell_signals.py` → `screen_daily_volume_price_signals.py` | 持仓 + 估值池 → §9.2 组合摘要回复 + `000_daily_scan_log.md` 置顶条目 | 健康度红黄绿分组、关注对象筛选与关注原因、口径标注与收盘定型 |

| 指令命中重蹈覆辙红线（无信号左侧买入 / 摊平加仓 / 下调、取消割肉价 / 拆除防护层、整体转左侧） | 个人体系 §17 + 本文件 §15.1 | 无（模型对照红线清单逐项核对） | 用户指令 → 劝阻答复 + 替代路径；坚持执行则 §10.4 off_system 前置记录 + `discipline_intervention` 日志 | 红线识别、引用病历纠正劝阻、如实留痕 |

**单票按需全链路研判（express）**：对任意指定股票（含池外），按 §5.4 三类判定 → 若 `worth_attention` 按 §5.7 分层 → 若 L1-L4 按 §6 估值定档（入池按 §6.2.1 分层×估值准入矩阵） → 若入池再按 §8 检查当日量价信号，任一段否决即停止并给出结论。express 使用与批量流程完全相同的标准，不得降低门槛，也不得跳过 §10 人工核对与 §11 风险过滤；各段结论照常写入对应产物文件与决策日志，使一次性分析可追溯、可复用。该路径用于"今天想知道某只股票值不值得买"的快速决策场景。

所有结论按 §2.1 写入决策日志；执行分工与禁改标准见 §15。

## 1. 目标

本流程用于固定“全市场质量筛选 -> 核心公司估值排雷 -> 每日右侧量价触发 -> 买入候选输出”的可重复执行体系。

核心原则：

1. 业务质量决定是否值得长期跟踪。
2. 估值分析用于排除过度透支的股票，而不是只寻找显著低估股票。
3. 量价信号只在高质量、估值合格的股票池内触发。
4. 每日输出的是买入候选，不是自动买入指令。
5. 每一次业务质量、估值、量价、买入候选、移出或降级结论，必须同步写入 `data/processed/a_share_workflow_decision_log.csv`，保留简要信息来源、结论、结论时间、输入文件、输出文件、数据口径和判断理由。

## 3. 核心概念

**值得关注公司**：
通过业务质量筛选后，值得持续跟踪的上市公司。

**临界待定公司**：
两种情形之一：缺少可靠资料、暂时无法明确其实际水平且无明显负面（含次新股披露不足）；或可判断但当前缺乏持久优势，但所处行业并非结构性绝望，未来可能因新产品、客户验证、技术路线、行业格局、资产重组或经营改善而重新获得复核资格。临界待定公司不进入每日量价扫描。

**垃圾公司**：
永久业务排除公司。只给**坐实的**造假/治理灾难或结构性绝望行业；公司层面“当前无护城河但行业并非绝望”属于临界待定，不判垃圾公司。垃圾判定可在任何轮次由坐实证据产生（不限于第一轮），但绝不由质量分层的 L5 表达。进入该类后，后续季度不再分析其业务是否改善，不再进入质量分层、估值排雷和每日量价扫描，只维护证券基础信息；唯一例外是 §5.4.7 的窄纠错路径（原判证据被推翻，或规则 7 的控制权变更且责任人出清）。

**质量分层**：
在第一轮三类初筛之后，只对 `worth_attention`（值得关注）公司执行。只根据护城河、业务类型、竞争优势可持续性、技术壁垒、资本复制难度、市场地位、现金流质量和不可替代性分为L1-L5，不考虑当前股价。L1-L4 是保留在值得关注内的质量档；L5 不是保留档，而是“不再值得长期关注”的判定，将该公司由 `worth_attention` 降级为 `boundary_pending`，等待未来硬触发再复核。`garbage` 是三类初筛层面的判定（可在任何轮次因坐实证据产生，见 §5.4.7），不进入质量分层，也不用L5表达。

**核心质量公司**：
质量分层为L1或L2的公司。

**核心估值合格池**：
L1-L4 值得关注公司**全量**进入每日量价扫描（v1.04），单一列表统一处理（v1.05）。估值档位由现价对照合理价区间**每日自动重定**（§6.2.1.6，无人工复核）：买入资格 = 质量 × 当日档位 过 §6.2.1 矩阵，升破带顶自动失去资格、回落带内自动恢复，档位变化在当日扫描报告列示即可；合理价区间本身只能由 §7 复核修改（价格改档、证据改带）。买入资格上一律排除高估、无法估值；层级越低准入越严——L1 合理估值（中性，甚至较高估）即可获得买入资格，L4 仅低估（经归一化口径复核）。

**买入候选**：
核心估值合格池中出现有效右侧量价信号的股票。

## 4. 总流程

```text
交易所最新A股证券名单
  -> 更新 data/raw/a_share_securities.csv
  -> 第一轮三类初筛
  -> 剔除垃圾公司
  -> 值得关注公司和触发复核的临界待定公司
  -> 季度质量审查
  -> A股值得关注公司列表
  -> L1-L5质量分层
  -> L1-L4全量估值排雷（分层×估值准入矩阵）
  -> 核心估值合格池（核心层L1/L2 + 战术层L3/L4）
  -> 每日量价扫描
  -> 买入候选输出
  -> 人工核对公告、研报和当日催化
  -> 决定是否建仓、等待回踩或放弃
  -> 建仓后写入持仓清单
  -> 每日持仓监控与卖出扫描
  -> 持仓动作：持有/加仓资格/减仓/止盈/清仓/风险预警
```

## 5. 阶段一：季度全市场质量审查

### 5.1 执行频率

每个季度报告披露周期后执行一次完整更新；在财报季内，按单家公司报告披露进度滚动更新。

### 5.2 输入

1. `data/raw/a_share_securities.csv`
2. 上一版 `data/processed/a_share_attention_triage.csv`
3. 上一版 `data/processed/a_share_watchlist_quality_tiers.csv`
4. 公司最新年报、半年报、季报、业绩预告、业绩快报
5. 公司公告、交易所问询函、投资者关系材料
6. 权威研报和专业机构研究材料
7. 同行业历史校准文件和既有L1/L2/L3参考公司

### 5.3 季度开始先更新A股证券名单

每个季度开始分析前，先基于交易所公开名单刷新A股证券基础名单，确保新上市公司进入第一轮初筛。

```bash
python3 scripts/fetch_a_share_universe.py \
  --output data/raw/a_share_securities.csv
```

执行要求：

1. 保留 `source_provider`、`source_dataset`、`source_retrieved_at_utc`、`source_url` 等来源字段。
2. 脚本同时把本次名单另存为 `data/raw/snapshots/a_share_securities_YYYYMMDD.csv`（按检索日期命名，不可变，ADR-0001）；主路径覆盖为最新版。对比上一份快照识别本季度新增上市公司。
3. 新上市公司进入 `attention_triage`，但上市时间过短、披露材料不足时，不直接归为垃圾公司，应先归为 `boundary_pending`。
4. 更新证券名单这一动作不构成投资结论，但后续由此产生的新上市公司初筛结论必须写入 `data/processed/a_share_workflow_decision_log.csv`。

### 5.4 第一轮三类初筛

第一轮初筛只回答一个问题：这家公司以后是否值得继续消耗研究精力。它是轻量、全覆盖的第一层，对每一家A股给出 `worth_attention`、`boundary_pending` 或 `garbage` 之一。

#### 5.4.1 总体原则

1. **逐家独立判断**：每家公司单独分析，禁止用单一指标对多家公司批量归类。同业对比可作为判断的输入，但不能取代逐家判断。
2. **以竞争力为准**：基于公司实际竞争力判断，不以盈利水平或市值高低为主要依据。股价上涨、题材热度本身既不是入选证据，也不是排除证据。
3. **轻量初筛**：第一轮只判断业务模式、是否具备明显且可持久的竞争优势、是否存在明显负面；不要求逐家通读年报，明显垃圾可快速判定。通读年报、研报等深度分析留到对 `worth_attention` 做 L1-L5 分层和权威深度复核。
4. **入选从严**：`worth_attention` 的优势必须能通过资本复制测试——资金充足的新进入者难以快速复制并侵蚀其回报；“一定程度的护城河”须收紧为“持久、难以复制”。不设数量目标，数量由严格标准自然决定；存疑则不放入 `worth_attention`。
5. **排除分两种**：`garbage` 是永久排除，只给造假/治理灾难与结构性绝望行业；公司层面“当前无护城河但行业并非绝望”应放 `boundary_pending`（可逆），不要因一时平庸就永久排除。
6. **判不了就 boundary**：缺少可靠资料、无法判断实际水平、且无明显负面 → `boundary_pending`（含次新股披露不足）。

#### 5.4.2 三类定义

| 分类 | 定义 | 后续处理 |
| --- | --- | --- |
| `worth_attention` / 值得关注公司 | 具备能通过资本复制测试的持久优势：护城河、强市场地位、定价权与话语权；或竞争优势、政策优势、产业地位；或相对竞争对手有明确的差异化优势或整体优势。以竞争力为准，不看盈利/市值，从严。 | 进入质量分层（L1-L5）和后续估值排雷 |
| `boundary_pending` / 临界待定公司 | 两种情形之一：(a) 缺少可靠资料、暂时无法明确其实际水平、且无明显负面（含次新股披露不足）；(b) 可判断但当前缺乏持久优势，但所处行业并非结构性绝望，未来有发展或重获优势的可能。 | 不进入每日扫描；在出现可靠资料，或财报、公告、订单、客户验证、产品突破、重大转型、行业结构变化等硬触发时复核 |
| `garbage` / 垃圾公司 | 永久业务排除。只给：① 造假/治理灾难；② 结构性绝望行业。 | 永久排除，不再进入季度质量审查、质量分层、估值排雷和每日量价扫描，只维护证券基础信息 |

#### 5.4.3 进入 garbage 的条件

只在以下情形判为 `garbage`（永久排除）：

1. 造假/治理灾难（须坐实）：财务欺诈、重大虚假陈述、严重监管处罚、控股股东资金占用、严重审计异常，或管理层造假/严重不诚信——以行政处罚决定、刑事立案/判决、审计否定或无法表示意见、交易所纪律处分等权威文书为准。
2. 治理/财务长期不透明：现金流、应收、存货、负债、治理结构长期无法解释。
3. 结构性绝望行业：所处行业或细分本身低壁垒、不可能形成持久护城河——一旦证明能赚钱，资金充足的新竞争者可以轻易进入并迅速替代，行业内没有任何公司能建立持久优势。

**证据等级（governance_fraud 必填）**：`garbage(governance_fraud)` 行必须在 `evidence_basis` 标注证据等级——`坐实`（有权威文书）或 `需核验`（依据公开报道/历史记忆，待对照文书）。`需核验` 的垃圾判定必须在下一个季度审查周期内对照公告/处罚文书确认；确认不了坐实证据的，降回 `boundary_pending` 并记 `garbage_review` 日志。**仅有造假嫌疑（长期蹭热点、公告与财报明显不匹配、夸大宣传）而无坐实文书的，判 `boundary_pending` 并写明核验触发条件，不判 `garbage`**——嫌疑类公司在嫌疑坐实前不进入每日扫描，实际风险由 §11 风险过滤器第 7 条兜底。

注意：公司层面“当前同质化、暂无护城河”，若行业并非结构性绝望，应放 `boundary_pending`，不判 `garbage`；“被更强同行全面覆盖”属于后续分层与同业校准的考量，不在第一轮判 `garbage`。

`garbage` 一旦坐实即永久排除，不因股价上涨、短期利润改善、媒体热度、主题炒作或低PE重新进入研究队列。只维护证券基础信息。唯一纠错路径见 §5.4.7：原判证据被权威信息推翻，或符合规则 7（治理灾难发生在前控股股东、控制权已变更且责任人出清）。

```text
capital_replicability_note, garbage_reason, garbage_subtype,
boundary_recheck_trigger, evidence_basis, reviewed_at_utc, workflow_version
```

`garbage_subtype` 取值：`governance_fraud` 或 `structural_industry`。

#### 5.4.5 行业校准锚

第一轮标准通过逐行业判例校准；每个行业的校准结论以可追溯方式记录在 `docs/peer-group-calibration/` 下对应文件，并在此沉淀可推广规则。

白酒行业校准（见 `docs/peer-group-calibration/a-share-baijiu.md` §1.10）得到的可推广规则：

1. **护城河需穿越周期验证**：`worth_attention` 要求护城河持久且已在完整下行周期中验证；护城河真实但穿越下行周期的能力尚未验证 → `boundary_pending`（可逆，验证后可升）。
2. **行业增长前景不是第一轮排除项**：行业长期增长走弱不在第一轮排除公司，只在 L1-L5 分层与估值中折价；第一轮以竞争力为准。
3. **传承品牌即资本难复制的护城河**：品牌 + 产区/原产地 + 老窖/不可替代实物资产 + 基酒/陈年库存 + 深耕渠道是典型持久护城河，此类行业并非结构性绝望。
4. **ST/困境的处理**：仅因连年亏损被 ST/困境、未坐实造假 → 不判 garbage，按竞争力判（通常 boundary）；`garbage(governance_fraud)` 需有坐实的造假/治理灾难，并核验公告。
5. **多元化拖累**：核心业务护城河真实、但被亏损非核心业务拖累、可比性差 → `boundary_pending`（剥离/重组后可逆），不直接 worth_attention 或 garbage。

面板行业校准（见 `docs/peer-group-calibration/a-share-display-devices.md` §1.5）补充：

6. **资本周期型制造业的护城河**（面板、半导体代工、光伏、LED、锂电等强周期、资本密集行业）：若龙头优势建立在**不可逆的结构性整合 + 客观巨大的资本/规模/技术壁垒**上（替代在客观上已很难），可判 `worth_attention`，即便穿越周期盈利尚未充分验证；周期性在 L1-L5 分层与估值折价。与规则 1 的区分：护城河**持久性本身存疑**（可能在需求下行中被侵蚀）时仍需穿越周期验证 → boundary；壁垒是客观结构性的则不需此前置证明。
7. **治理灾难的可逆性**：治理灾难发生在**前控股股东**、现已更换控制权并重整 → `boundary_pending`（控制权变更=复核触发），不判永久 garbage；`garbage(governance_fraud)` 留给未解决/仍在持续、或同一责任人仍在位的造假与治理灾难。

建筑装饰行业校准（见 `docs/peer-group-calibration/a-share-decoration-construction.md` §1.5）补充：

8. **结构性绝望行业（structural_industry garbage 的适用）**：当行业商业模式结构性破损——低进入门槛、垫资/应收/强地产或单一客户依赖、优势 execution-heavy 而非持久护城河、历史规模或当前利润不代表持久回报——判 `garbage(structural_industry)`，**且适用于相对龙头**（execution、品牌、历史规模在破损模式里不构成持久护城河）。仅当存在**结构确实不同的更高壁垒子赛道**（如高端幕墙系统 vs 普通室内装修）才碗出到 `boundary`。结构性判决在子行业/子赛道粒度上做。

第一轮全量执行中校准补充：

9. **基础设施垄断**（机场、港口、高速、水务、燃气等）：有不可复制的区域垄断地位，但回报受管制、无定价权、特许期有限，护城河不转化为超额回报 → `boundary_pending`（可逆）；出现非航/免税/提价/资产注入等明确改善再升 `worth_attention`。
10. **极端牌照但回报受管制（核电等）**：即使牌照壁垒极强（如核电全国仅 2-3 家运营商），只要回报受管制、无定价权、护城河不转化为超额回报 → `boundary_pending`（规则 9 的延伸）；电价市场化、资产注入或非管制收益占比提升再升 `worth_attention`。
11. **银行**：只有穿越周期的优质 franchise（持续低成本存款、风控、显著高于同业的 ROE，如宁波银行）才判 `worth_attention`；普通、同质化、强周期或主要靠规模的银行 → `boundary_pending`。
12. **品类垄断与 capped-capacity 商品**：防过度纳入清单不能误伤两类真实护城河：
    - 细分品类龙头若已证明**品类垄断/全球领先 + 高毛利/高ROE/定价权 + 穿越周期超额回报**，不按“普通细分件”降级，仍可判 `worth_attention`（如美亚光电色选机）。
    - 商品行业若存在**政策性产能红线/指标稀缺 + 低成本曲线 + 一体化规模优势**，产能指标可视为类资源牌照，低成本一体化龙头可判 `worth_attention`；仅有产能、仅有成本优势或无定价权的普通周期公司仍判 `boundary_pending`。

#### 防过度纳入清单（worth_attention 的否决项）

worth_attention 从严。出现以下情形，默认 `boundary_pending`，不纳入 worth_attention：

1. **“研究价值/值得理解”不是理由**：worth_attention 要求持久、难复制、能转化为超额回报的护城河；“值得理解 ≠ 值得观察”。
2. **护城河理由自带对冲**：理由里出现“规模弱/偏小/需跟踪/研究价值/受益于景气/有望”等对冲措辞 → 默认 boundary。
3. **强位置 ≠ 超额回报护城河**：仅“细分/niche 能力强”，或强市场地位但属中游/低毛利/组装代工/客户高度集中 → 默认 boundary。
4. **资源类三要素**：需同时具备稀缺 + 低成本曲线 + 规模/储量；仅“有矿/有资源”不够 → 默认 boundary。
5. **景气受益不是护城河**：AI 资本开支、商品涨价、补贴等景气本身不构成护城河；要问景气退潮后是否仍有难复制壁垒。
6. **规制回报/无定价权**：含极端牌照（核电、规制公用）与普通银行业务 → boundary（规则 9/10/11）。
7. **与已判同行一致**：同行业/同类型中，更大或更强的同行若已判 boundary，更小的不应判 worth_attention。

豁免：若公司满足规则 12 的品类垄断或 capped-capacity 低成本龙头条件，不能仅因“细分”“周期”“成长空间有限”降为 `boundary_pending`；成长空间和估值吸引力留到 L1-L5 分层与估值阶段处理。

过渡期依赖：重扫完成后必须依次重做「L1-L5 分层 → L1/L2 估值排雷 → 重建核心估值合格池」。现有 `a_share_watchlist_quality_tiers.csv`、估值表与核心池基于旧分层，过渡期内仅作参考，不作为新增买入依据的最终口径。

### 5.4.7 attention_class 状态迁移表

三类状态的全部合法迁移。任何迁移必须写决策日志，改判/纠错必须填 `supersedes_decision_id` 指向被替代结论。

| 迁移 | 触发条件 | 决策类型 |
| --- | --- | --- |
| `worth_attention` → `boundary_pending` | 质量分层判 L5（不再值得长期关注）；或复核发现持久优势证伪 | `quality_tier_review` / `attention_triage` |
| `worth_attention` → `garbage` | 坐实造假/治理灾难（任何轮次，见 §5.4.3 证据等级） | `attention_triage` 或复核 |
| `boundary_pending` → `worth_attention` | 硬触发（可靠资料、财报改善、订单、客户验证、产品突破、重组、行业结构变化）后复核通过 | `attention_triage` |
| `boundary_pending` → `garbage` | 坐实造假/治理灾难，或子行业被判结构性绝望 | `attention_triage` |
| `garbage` → `boundary_pending`（唯一纠错路径） | ① 原判所依据的证据被权威信息推翻（如处罚撤销、判决改判）；② 规则 7：治理灾难属前控股股东、控制权已变更且责任人出清；③ `需核验` 等级在核验期内确认不了坐实证据 | `garbage_review` |

补充约定：

1. `garbage` 不可直达 `worth_attention`；纠错只回 `boundary_pending`，再按硬触发正常复核。
2. `boundary_pending` 内区分两种子情形并写入 `boundary_recheck_trigger`：`insufficient_disclosure`（资料不足，含次新股）与可逆业务否决（可判断但当前缺乏持久优势）；两者复核触发不同（前者=资料可得，后者=业务硬触发）。
3. 结构性绝望行业（`structural_industry`）判决原则上不可逆；仅当公司实质转型脱离破损模式（对照汇绿生态/东方新能判例）或子赛道被证明结构不同，方可经 `garbage_review` 回 `boundary_pending`。
4. 质量分层（L1-L5）只在 `worth_attention` 内运作，永不产生 `garbage`。

### 5.7 质量分层标准

| 层级 | 定义 | 仓位资格 |
| --- | --- | --- |
| L1 | 顶级核心候选。行业或细分赛道核心龙头，具备极强护城河、技术壁垒、资源壁垒、品牌壁垒、平台能力或监管壁垒，资本充足的新进入者也难以短期复制和超越。 | 低估/较低估/中性/较高估可买（准入与入场阶段见 §6.2.1/§8.13；仓位档见 §13） |
| L2 | 准核心候选。护城河明确，但存在周期、政策、成长空间、业务结构、验证阶段或同业地位折扣。 | 低估/较低估/中性可买（较高估仅 watch_only）（§6.2.1/§8.13；仓位档见 §13） |
| L3 | 战术观察。具备产业机会、反转机会、技术期权、局部壁垒或周期修复弹性，但护城河、现金流、市场地位或不可替代性不足以进入核心层。 | 低估/较低估可买（中性仅 watch_only）（§6.2.1/§8.13；仓位档见 §13） |
| L4 | 零仓观察。可理解、可偶尔复核，但护城河强度、催化清晰度、同业差异或证据质量不足以进入前三层。仍属值得关注。 | 仅低估可买（结论须经归一化口径复核，不加仓）（§6.2.1/§8.13；仓位档见 §13） |
| L5 | 移出值得关注、降级为临界待定（非永久排除）。低壁垒、易复制、被更强同行全面覆盖、现金流质量差，或主要靠题材/周期而无持久优势。判为L5表示不再值得长期关注，`attention_class` 由 `worth_attention` 降为 `boundary_pending`，等待未来硬触发再复核。 | 不建仓；垃圾判定属三类初筛层（§5.4.7），不用L5表达 |

### 5.7.1 分层校准细则

（自原权威深度复核协议并入。）分层完成足够数量后整体应呈金字塔形：上层是稀缺关注名额，不是"公司还不错"的描述。

1. **L1 市值中性**：L1 留给能对抗现有最强锚点的核心候选；当前市值、指数权重、流动性不得作为 L1 的必要条件。
2. **L1 三种子类型**，避免混用理由：
   - 持久护城河/现金流锚：护城河极难复制、现金转化与利润质量卓越，即使行业增长放缓也可为 L1；行业增长弱只记入估值与仓位备注，不单独降档。
   - 战略瓶颈/平台锚：掌握关键技术、系统平台、资源、标准、客户认证层或供应链瓶颈，且资金充足的进入者难以替代。
   - 小市值例外：权威证据显示真正不可替代的利基、全球/全国领先地位与高切换成本时，小市值不封顶质量档位，只提高证据要求、并可能降低最终仓位。
3. **L2 不因估值降档**：L2 用于优势明确但存在周期、空间、瓶颈验证、治理或对比 L1 锚点位置等实质性折扣的公司；当前估值敏感性属于估值阶段，不得单独用于降质量档。
4. **L3 不是中间桶**：必须至少有一个明确的战术关注理由（行业催化、右侧触发候选、周期拐点、局部瓶颈、差异化技术、股东回报催化或有据可查的困境反转路径）；理由只是"公司不错/可能增长/可能反弹"则降 L4。
5. **L4 是保守默认档**：可理解、可偶尔复核，但护城河强度、催化清晰度、同业差异或证据质量不足以进前三层。
6. **锚点双重对照**：同业对照不仅比弱者，必须与已定 L1/L2/L3 锚点比较；不如现有 L3 锚点的不进 L3。
7. **医疗器械**：平台型 L1 需产品广度被共享医院渠道、装机保有量、服务网络、质量体系、全球注册能力、研发复用与现金转化共同强化，仅产品线多不够；电生理、血管介入、高端影像、内窥镜、植入物、耗材、生物材料等专科高壁垒公司默认从 L2 起，除非能独立证明品类定义级地位；被 L1 平台收购是技术验证但不自动升 L1，协同效应记为升档触发而非既成事实；产品广度稀释 ROIC、拖累现金转化或关键产品线丢份额时平台降档。
8. **AI/半导体链**：不得把短期利润爆发等同于更强护城河。光模块、PCB、封装、半导体设备、EDA、接口芯片等必须同时评估「当前瓶颈强度」与「穿越周期的技术/生态护城河」：瓶颈强但持久性弱者可作战略瓶颈锚 L1，但必须显式标注产品周期、客户集中与定价风险；护城河更深者不得仅因近期业绩弹性低而排在当前周期赢家之后。
9. **禁止捷径**：不得仅凭行业关键词、同业标签或历史分数派档；聚合站/F10 简介只作线索不作证据；不得仅凭当前盈利推断护城河；不得跳过资本复制测试；不得让当前估值决定档位。

### 5.8 质量审查执行规则

质量审查只判断业务质量，不考虑当前股价和估值。

输入材料：

1. 公司名称和股票代码。
2. 所属行业、同行组和主要竞争对手。
3. 最新年报、半年报、季报、业绩预告和业绩快报摘要。
4. 公司公告、交易所问询函、监管处罚、投资者关系材料。
5. 权威研报和专业机构研究材料。
6. 当前已有 `attention_class`、质量分层和策略标签。
7. 同行业L1/L2/L3参考公司。

执行步骤：

1. 说明公司主要业务、利润来源和业务结构。
2. 识别护城河来源：品牌、资源、技术、客户认证、成本、渠道、网络效应、监管牌照等。
3. 执行资本复制测试：判断资金充足的新玩家能否快速复制并超越。
4. 与同行比较，判断是否被更强公司全面覆盖，或是否具备差异化不可替代位置。
5. 判断当前业务优势是否可持续，并做前瞻侵蚀检验：列出未来 2-3 年最可能侵蚀护城河的因素（技术替代、政策/集采、携资进入、大客户或核心团队流失），评估概率与影响，写入 `moat_summary` 或 `tier_reason`。
6. 检查一票否决事项：财务造假、治理风险、现金流恶化、低壁垒高竞争、媒体炒作和造假嫌疑。
7. 先确认 `attention_class`：默认维持现状；仅当出现坐实负面（→`garbage`）或持久优势证伪（→`boundary_pending`）时按 §5.4.7 迁移表改判，并填 `supersedes_decision_id`。
8. 如果改判 `garbage`，必须写明垃圾分类原因与证据等级（§5.4.3），并记录后续永久排除。
9. 如果不是 `garbage`，再根据业务质量分为L1/L2/L3/L4；若业务质量只够L5（低壁垒、被更强同行全面覆盖等），不保留在值得关注内，降级为 `boundary_pending`。
10. 给出观察池动作：新增、维持、降级或移除。
11. 将来源、结论、时间、输入文件、输出文件和简要判断理由写入结论日志。

输出字段：

```text
security_code
security_name
attention_class
quality_tier
primary_strategy_tag
moat_summary
capital_replicability
peer_comparison
garbage_reason
boundary_recheck_trigger
tier_reason
watch_action
evidence_sources
decision_log_summary
evidence_available_at
```

`evidence_available_at`（v1.26）：本次质量复核所依据的最新财务资料公开可得日（公告日，非报告期末），与 §6.6 估值侧同名字段同口径。**每次质量复核完成后必须与 `reviewed_at_utc` 一并更新**；供 §7.2 的 `quality_cutoff` 兜底比较使用，留空则退化为纯复核日比较。

## 6. 阶段二：值得关注公司估值排雷（L1-L4）

### 6.1 执行范围

对全部 L1-L4 值得关注公司执行估值分析（worth_attention 经从严初筛后总数少于300家，全量估值成本可控且避免 L3/L4 中的深度低估机会被系统性忽略）。分层只决定**买入准入门槛与仓位上限**（§6.2.1），不改变估值方法本身。

### 6.2 输出分类

| 估值档位 | 含义 | 是否进入核心估值合格池 |
| --- | --- | --- |
| 低估 | 当前市值明显低于保守或正常估值，安全边际充分 | 按 §6.2.1 矩阵（L1-L4 均可） |
| 较低估 | 当前价格有明显吸引力，但存在周期、政策、业绩验证或行业折扣 | 按 §6.2.1 矩阵（L1-L3） |
| 中性 | 估值大致合理，未明显透支未来 | 按 §6.2.1 矩阵（L1/L2） |
| 较高估 | 略贵，但bull case尚未完全定价，且后续仍可能上修 | 按 §6.2.1 矩阵（仅L1常备；L2 为 watch_only 仅观察） |
| 高估 | 已计入极端bull case，或需要过度乐观假设才能成立 | 不可买；每日随扫，现价回落带内即自动恢复相应档位与资格（§6.2.1.6） |
| 无法估值 | 缺少足够数据或关键假设不可验证 | 不可买；每日随扫，无可靠带不自动定档，改档仅经 §7 复核 |

### 6.2.1 分层×估值准入矩阵（买入门槛随质量层级递严）

质量越高，买入估值门槛越宽、允许的右侧入场阶段越早；质量越低，要求的安全边际越深、要求的右侧确认越充分。矩阵同时决定入池资格、常备可买档位与所需入场阶段（v1.02：赔率闸门退役——估值对买入的全部约束由档位、合理价区间与本矩阵承担，§10 不再计算赔率）；档位为**当日价格自动定档**（§6.2.1.6，v1.05），矩阵资格随之每日自动更新：

| 层级 | 可入池的估值档位 | 池内层 | 常备可买档位 | 所需右侧入场阶段（§8.13） |
| --- | --- | --- | --- | --- |
| L1 | 低估 / 较低估 / 中性 / 较高估（需盈利预测持续上修或明确催化，§6.6） | 核心层 | 全部入池档位 | 低估=一段；较低估=二段；中性=三段；较高估=四段 |
| L2 | 低估 / 较低估 / 中性 / 较高估（仅 watch_only） | 核心层 | 低估 / 较低估 / 中性 | 低估=二段；较低估=三段；中性=三段（v1.06） |
| L3 | 低估 / 较低估 / 中性（仅 watch_only） | 战术层 | 低估 / 较低估，且必须有明确战术理由兑现路径 | 低估=三段；较低估=三段 |
| L4 | 仅低估（结论须经归一化口径复核，防一次性利润粉饰） | 战术层 | 低估（不加仓） | 四段 |

执行说明：

1. 矩阵是**买入准入**，不是卖出指令：已持仓股票估值档位滑出准入范围时按 §14 风险预警 5 复核，不自动清仓。
2. L3/L4 的战术层股票出现买入信号时一律先经 §10 人工闸门（§8.10 优先级 C/D），不允许仅凭脚本信号建仓。
3. 分层或估值档位任何一侧变化后，重跑池物化脚本即自动按矩阵重算入池资格。
4. **事件通道关闭（v1.02，用户决定；取代 v23/v24）**：未过矩阵的组合一律**可见不可买**，不存在绕过估值的当日买入通道。买入资格恢复的两条路：①价格路径——现价变化使当日自动定档过矩阵（§6.2.1.6，次日自动生效）；②证据路径——政策/事件/财报经 §7.4 复核（含第 6 条当日 express 义务）修改合理价区间或质量分层。24 小时异动响应义务（个人体系 §9.4）不变。
5. **watch_only 仅观察层（v20）**：L1-L4中估值为低估/较低估/中性/较高估但未过本矩阵的组合（当前主要为L2×较高估、L3×中性、L4×非低估），物化进池文件供每日扫描可见，不具备买入资格；高估/无法估值不物化。
6. **档位价格自动定档（v1.05，取代 v1.02/v1.04 的待复核机制）**：档位由现价对照合理价区间**每日自动重定，双向生效、无人工复核**——现价 > 1.2×`fair_price_high` = 高估；带顶 ~ 1.2×带顶 = 较高估；带内 = 中性；带底以下按空间（区间中值/现价 − 1）≥ 40% 分低估、否则较低估；无法估值无可靠带，不自动定档（改档仅经 §7 复核）。买入资格随当日档位按本矩阵自动更新：升破带顶自动失去资格、回落带内自动恢复；档位变化只需在当日扫描报告第二节与刷新汇总日志列示（快照差分见 §6.7.7），不设复核前置。L1×较高估的 §6.6 上修/催化附加条件仍在 §10 闸门核对。**分工恒等式：价格改档、证据改带**——合理价区间本身仍只能由 §7 复核（财报/预告/事件）修改，估值对买入的全部约束都发生在档位与带上。阈值（1.2×带顶、40% 空间）为 2026-07-17 初始校准，修订先改本文件。定档**双向均不限幅**（v1.14，2026-07-21 用户澄清后确认）：价格跌得足够深即可从高估直接定到低估，无一档限制、无复核前置——v1.13 曾引入"单向限档+下行越档复核"，系对用户质疑的误读（用户误以为漂移展示是隔日跳档），当日即撤销；展示口径上池 MD 的 `审定档→现档` 箭头左端是**审定档**（非昨日档），当日变化另见扫描报告与刷新日志。

### 6.3 估值原则

1. 估值只用于排除过度高估的核心质量公司。
2. 不因单纯PE高而排除处于产业爆发、研发投入期、盈利爬坡期的公司。
3. 不因单纯PE低而认定低估。
4. 对一次性亏损、一次性收益、研发投入、股权投资收益、公允价值变动、资产减值、补贴、会计处理变化进行归一化处理。
5. 对周期股使用中枢利润、资源NAV、商品价格中枢，不使用周期顶部单年利润。
6. 对产业链爆发股使用2-3年正常化利润和需求、瓶颈、利润三张票，不机械使用TTM PE。
7. 对早期高研发公司使用收入质量、毛利率成熟路径、研发效率、客户验证、产品壁垒和未来正常化利润，不机械使用当前亏损。

### 6.4 特殊估值失真处理

出现以下情形时，必须使用归一化估值：

1. 单季度或单年度存在一次性亏损。
2. 单季度或单年度存在一次性投资收益、公允价值收益或资产处置收益。
3. 公司处于研发投入期，当前利润被研发费用、产能爬坡、销售投入压低。
4. 公司处于行业周期底部，当前利润低于中枢利润。
5. 公司处于产业爆发前夜，当前利润尚未体现订单、产能、技术路线或客户验证。
6. 公司处于商业模式转换期，旧业务拖累利润，新业务尚未充分释放。

归一化估值字段：

```text
normalized_profit = 扣非净利润 - 一次性收益 + 一次性亏损调整 + 合理研发/产能爬坡归一化调整
normalized_margin = 成熟业务合理净利率
normalized_revenue = 可验证订单、产能、行业需求支持下的未来2-3年收入
normalized_market_cap = normalized_profit * 合理估值倍数
```

收入质量三分类（归一化的第一步）：

| 收入类型 | 示例 | 处理 |
| --- | --- | --- |
| 经常性收入 | 产品销售、稳定服务费、可持续订单 | 计入经常性利润，可外推，适用正常估值倍数 |
| 一次性收入 | BD授权首付款、资产处置、大额补贴、公允价值变动 | 从经常性利润中剔除 |
| 里程碑/或有收入 | BD后续里程碑款、对赌兑现 | 不并入经常性利润，按兑现概率作为期权价值单独估算 |

```text
经常性PE = 当前市值 / 经常性利润
```

一次性收入占当期利润比例高的公司，必须用经常性PE替代表观PE参与档位判定，防止被一次性利润粉饰的低PE误导。

### 6.5 分策略估值方法

#### A：DCF / 现金流复利型

指标：

1. PE历史分位。
2. 自由现金流收益率。
3. 股息率和回购注销率。
4. ROE/ROIC稳定性。
5. 未来3年收入和利润增速。

预期年化收益：

```text
预期年化收益 = FCF收益率 + 保守利润增长率 + 股息/回购收益率 + 估值修复年化贡献
```

档位标准见 §6.6 总表。

#### B：烟蒂深度低估型

保守清算价值：

```text
保守清算价值 = 现金 + 0.8 * 应收账款 + 0.5 * 存货 + 0.3 * 固定资产 - 总负债
```

档位标准见 §6.6 总表。

适用说明：估值排雷只对 L1/L2 执行，而典型烟蒂公司很少具备 L1/L2 级护城河，B 类在核心估值合格池内近似空集。烟蒂机会实际主要出现在 L3 战术观察（§8.10 优先级C 人工复核路径）；本模型为该路径与个别 L2 特例保留。

#### C：GARP成长型

指标：

1. 未来3年利润CAGR。
2. 归一化PEG。
3. 收入质量和市场空间。
4. 毛利率、净利率、经营现金流转化。
5. 增长是否可防守。

档位标准见 §6.6 总表。

#### D：产业链爆发 / 关键瓶颈型

必须同时评估：

1. 需求票：下游需求真实增长。
2. 瓶颈票：公司处于供给瓶颈或关键不可替代环节。
3. 利润票：需求和瓶颈能显著转化为上市公司收入和利润。

未来合理市值：

```text
未来合理市值 = 未来2-3年正常化净利润 * 合理PE
```

档位标准见 §6.6 总表。

#### E：落难白马型

指标：

1. 核心业务是否被结构性破坏。
2. 利润预期是否停止下修。
3. 现金流是否健康。
4. 管理层资本配置是否改善。
5. 估值是否低于正常化盈利水平。

档位标准见 §6.6 总表。

#### F：垄断资源型

指标：

1. 资源储量和NAV。
2. 成本曲线位置。
3. 商品价格中枢。
4. 穿越周期现金流。
5. 扩产能力和资本纪律。

档位标准见 §6.6 总表。

#### G：股东回报型低估

指标：

1. PB/ROE匹配度。
2. 分红率。
3. 股息率。
4. 回购注销率。
5. 资产质量。

档位标准见 §6.6 总表。

### 6.6 估值审查执行规则

估值审查只对L1/L2核心质量公司执行，目标是排除过度高估，不是只寻找显著低估股票。估值必须先确定策略标签，再使用对应模型。

输入材料：

1. 公司名称、股票代码、质量分层和策略标签。
2. 最新价格、市值、PE、PB、股息率、回购率和历史估值区间。
3. 最新财报核心指标：收入、扣非净利润、经营现金流、毛利率、净利率、ROE/ROIC、资产负债率、应收、存货、资本开支。
4. 未来3年一致预期和权威研报核心假设。
5. 行业周期位置、商品价格中枢、产业链供需状态或渗透率阶段。
6. 一次性收益、一次性亏损、研发投入、产能爬坡、周期底部、商业模式转换等估值失真因素。
7. 当前市值与bull case合理市值、正常化利润估值或资源NAV的差距。

执行步骤：

1. 确认适用估值方法：DCF/现金流复利、烟蒂深度低估、GARP、产业链爆发、落难白马、垄断资源、股东回报型低估。
2. 适用性前置检验：先确认策略标签仍然成立（增长被证伪的GARP、把一次性利润当成长的公司应重贴标签），再确认所选模型对该公司当前状态有效。典型失效场景：PE/PEG用于周期股、亏损公司或一次性收入占比高的公司；PB用于轻资产公司；PS用于利润率无改善路径的公司；DCF用于现金流为负或极不稳定的公司。方法失效时改用替代模型或归一化口径；无可用方法则判"无法估值"。
3. 判断当前PE/PB/PEG是否失真；如失真，使用归一化估值（含收入质量三分类与经常性PE）。
4. 写出估值模型关键输入，例如归一化利润、未来2-3年利润CAGR、合理PE、NAV、中枢FCF收益率、股息率或回购率。
5. 反向预期拆解：从当前市值反推市场隐含的增速、利润率或永续假设，与自己的关键输入对比，明确"市场已定价什么、预期差在哪"；隐含假设是否已达到bull case水平，是 `bull_case_priced_in` 的判定依据。
6. 给出bull case核心假设，并判断当前价格是否已经反映bull case。
7. 分为：低估、较低估、中性、较高估、高估、无法估值。
8. 给出合理价区间 `fair_price_low`/`fair_price_high`：该股按对应策略模型处于"中性"档的价格带（如 D 档为 bull 合理市值×80%-100%、C 档为归一化 PEG 1.0-1.5 对应价格），换算依据写入 `fair_price_basis`；区间必须与所定档位自洽（低估的估值价应低于区间下沿，高估应高于区间上沿，中性应落在区间内），锚点数据不足时按档位标准带换算并在 basis 注明。
9. 判断是否进入核心估值合格池。
10. 给出等待右侧触发时需要观察的关键指标。
11. 将来源、结论、时间、输入文件、输出文件和简要判断理由写入结论日志。

估值模型和档位：

| 策略类型 | 模型 | 低估 | 较低估 | 中性 | 较高估 | 高估 |
| --- | --- | --- | --- | --- | --- | --- |
| DCF/现金流复利型 | 预期年化收益 = FCF收益率 + 保守利润增长率 + 股息/回购收益率 + 估值修复年化贡献 | >=12% | 8%-12% | 6%-8% | 4%-6%，且L1或有明确催化 | <4%，或PE处历史90%分位以上且增长放缓 |

| GARP成长型 | 归一化PEG | PEG <=0.7且增长可防守 | 0.7-1.0 | 1.0-1.5 | 1.5-2.0且盈利预测持续上修 | >2.0且无持续上修证据 |

### 6.6.1 单票本地台账（v1.02：季度财务、研报、预告兑现）

目的：估值复核先读本地台账、只增量补新数据，避免每次全网重检（token 成本）与口径漂移；台账带完整溯源，估值结论引用台账行而非临时检索结果。

1. **季度财务台账** `data/processed/fundamentals/<代码>_<名称>.md`：池内标的（含 watch_only 与高估/无法估值排除名单）每票一份。按报告期一行记录：营收、扣非净利润、经营现金流、毛利率、净利率、ROE、资产负债率与应收/存货/资本开支要点；每行注来源（公告标题或数据源）、公告日、检索日。财报或预告披露后随 §7 复核增量追加，不重写历史行。
2. **研报跟踪台账** `data/processed/analyst_reports/<代码>_<名称>.md`：逐份研报一行——发布日、券商、评级、目标价、未来三年营收/归母/EPS 预测与隐含增速、核心假设一句话。每次估值/事件复核时检索是否有新研报，只补增量。一致预期一律取**中位数口径**，禁用单份乐观研报作带锚；研报预测须与后续实际兑现对照回填（命中/偏差方向），逐步形成券商可信度记录。

   **2a. 股本口径校验（v1.26，取一致预期前的强制第一步）**：用 **研报归母 ÷ 研报 EPS 反算隐含股本**，与**现股本**（`总市值 ÷ 现价`）比对。**两者不一致即说明研报 EPS 为送转/增发前口径**——东财 `ProfitForecast` 等接口对研报预测 EPS **不作追溯除权调整**，而同表的历史实际 EPS 已按现股本重算，两列口径不同源。此时**一律改用「归母净利」口径建带**（归母是股本无关量），并按现股本自算 EPS = 归母 ÷ 现股本；**禁止直接使用研报 EPS 及由其推算的 PE/PEG**，也禁止把跨越送转日的 EPS 序列当作预测变化读取。

   校验未做会产生两类错误，两类都已在 2026-07-30 同日命中：①**伪下修**——东鹏饮料（605499）2026-05-18 每 10 股转增 3 股，转增前研报 26E EPS 9.39-9.94、转增后 6.91-7.68，直接读取会误判为"6 月起券商集体大幅砍预测"，归一（÷1.3）后实为 6.91-7.68 的窄区间、**不存在下修**；②**污染均值**——同接口"近六月平均 EPS"混合送转前后口径（东鹏 9.166），**该值及其 PE 一律不可作带锚**，但同表 `PARENT_NETPROFIT` 均值不受股本影响、可用。另一判例：乐鑫科技（688018）研报隐含股本 1.672 亿 vs 现股本 2.3438 亿（比值 1.402）。

   校验结果与归一化倍数须写入研报台账顶部的醒目提示行，供后续复核直接复用。
3. **业绩预告与兑现对照**：预告/快报当日按 §7.5.5 express 复核；财务台账内为每个报告期维护「预告区间 → 当时一致预期 → 实际」三栏，兑现偏差作为下一次估值假设的第一修正项，并用于验证公司是否兑现业绩预期。
4. 台账是估值输入的缓存与审计线索，不是结论文件：档位与合理价区间的唯一口径仍是估值表与核心池（§6.6/§6.7）。

估值审查输出的是估值结论，脚本只负责把已审查完成的估值表物化为每日扫描输入，不重新创造估值意见。

8. 业绩预告物化（v1.04；v1.09 起不在 MD 展示；v1.16 起每日刷新）：`scripts/fetch_a_share_earnings_forecasts.py` 将东财业绩预告接口物化为 `data/interim/a_share_earnings_forecasts.csv`（`--report-date` 缺省自动取最近一个已结束的季度报告期末，可显式指定，适用一季报/中报/三季报/年度各预告季；字段含代码、报告期、公告日、指标口径 004归母/005扣非/006营收、预告区间、同比增幅、去年同期、预告类型、检索时间与来源）。该文件**不是一次性物化，而是每个扫描日经 §9.1 步骤 0 重抓**——预告披露是逐日到达的事件流，停更的文件等于关闭 §7.4/§7.5.5 的事件入口（判例：睿创微纳 2026-07-20 盘后预告，7/17 的旧文件使其三个交易日不可见）。该文件**只作 §7.5.5 express 复核队列的输入**，且刷新汇总**不得只报覆盖数**：必须列出**待复核名单本身**（代码+名称+公告日+披露类型；判定=预告/快报/正式报告公告日的最大者晚于 max(`valuation_reviewed_at`, `evidence_available_at`)，缺失时回退 `pool_as_of`，v1.18 起为三类披露并集口径），并标注披露文件检索时间——检索日早于扫描日时加"⚠️数据过期"警告并按 §9.1 步骤 0 当场重抓。待复核名单逐票按 §7.5.5 express 复核闭环（复核更新 `valuation_reviewed_at`/`valuation_evidence_event` 后自动移出名单）；名单非空时写入扫描报告第二节与第三节待办。复核完成后其影响体现为 估值时间/估值事件 两列与合理价区间的更新，预告具体数字不进入池 MD。
9. 定期报告与业绩快报披露物化（v1.18）：`scripts/fetch_a_share_report_disclosures.py` 将东财**正式定期报告披露**（RPT_LICO_FN_CPD，公告日=实际披露日，含归母/营收实际数与同比）与**业绩快报**（RPT_FCI_PERFORMANCEE）物化为 `data/interim/a_share_report_disclosures.csv`（`disclosure_type` 区分 periodic_report/express_report；`--report-date` 缺省口径同预告脚本）。与预告文件同为**每个扫描日经 §9.1 步骤 0 重抓**的事件流入口：仅抓预告等于对快报与正式报告闭眼（判例：华润三九 7/15、大族激光 7/21（归母 +163%）H1 快报在仅预告机制下持续不可见，直至 2026-07-22 本文件增设才被发现，两只均已超期）。该文件供 报告更新队列（§7.2/§7.3 公告日触发）与 待复核名单（要求 8 并集口径）使用；同一披露季内正式报告公告日晚于快报/预告的，正式报告构成新一次复核触发（快报/预告先行复核不豁免正式报告复核，实际数与预告的兑现偏差按 §6.6.1.3 回填台账）。

### 6.8 海外关注清单（非A股，观察口径，v1.22）

用户长期关注但不在 A 股上市的公司（港股、美股、韩股），用与 A 股完全相同的质量与估值口径回答三件事：**质量几档、该用哪个模型、现价贵不贵**。个人投资体系是账户级总规则（覆盖 A 股/港股/美股），本节只是把该体系的分层与估值口径延伸到非 A 股标的上，不改变本文件其余章节的 A 股范围。

**边界（硬约束）**：

1. **一律不可买、不构成买入候选**：本清单不写入 `a_share_core_valuation_pool.csv`，不进 §8 每日量价扫描，不走 §10 买入前闸门，§6.2.1 分层×估值准入矩阵不适用（`buy_eligibility` 恒为 `off_pipeline_watch_only`）。清单里出现「较低估」不等于可买。
2. **不污染 A 股机器口径**：A 股扫描/披露/持仓脚本的数据源均为东财与腾讯 A 股接口，海外标的既无对应的预告/快报接口，也无涨跌停、量比与 §8 均线体系的同源数据；因此海外清单单独建表、单独快照，A 股主表的只数统计（如「261/261」）不含海外行。
3. **不降低门槛**：质量分层用 §5.7/§5.7.1，策略标签与估值模型用 §6.5/§6.6，归一化与失真处理用 §6.3/§6.4，档位自动定档用 §6.2.1.6。唯一豁免是 §5.7.1 的金字塔校准——本清单是用户点名的自选名单而非全市场筛选结果，层级分布天然偏上，不作分布约束。
4. **行序**：附表与 A 股主表一致按**质量档 L1→L4**排列（渲染时排序，同档内保持清单原序 港股→美股→韩股），CSV 本身按市场分组存放，两者不必同序。
5. **证券与公司分离**：同一公司的不同上市线是不同标的。清单按**实际定价用的那条线**建行并在 `notes` 写明（例：阿里巴巴/京东取港股线；SK 海力士的美国线只有 OTC ADR、报价停更且流动性不足，故取 KRX 主线）。

**单文件承载**：海外清单不分设分层表与估值表，`data/processed/overseas_watchlist_valuation.csv` 一行一家，字段为 §6.6 输出字段加四个市场字段：

```text
market_type（HK/US/KR）  security_code  security_name  exchange  currency
quality_tier  tier_reason  strategy_tag  valuation_tier  valuation_method
valuation_batch_id  valuation_price  valuation_price_as_of  total_market_cap_bn（十亿，本币）
valuation_pe_ttm  valuation_pb  fair_price_low  fair_price_high  fair_price_basis
normalized_valuation_used  normalized_profit_or_value  bull_case_assumption  bull_case_priced_in
valuation_reason  tracking_metrics  evidence_sources
valuation_reviewed_at  valuation_evidence_event  evidence_available_at
buy_eligibility（恒 off_pipeline_watch_only）  notes
```

**币种与行情**：现价、合理价区间、空间一律用该标的的**交易货币**（港股 HKD、美股 USD、韩股 KRW），跨市场不可直接比较；`total_market_cap_bn` 同为本币。行情与 A 股同源腾讯快照，字段布局按市场不同，由 `scripts/overseas_quotes.py` 承担（HK 有 PE/PB，US 无 PB，KR 无 PE/PB——缺失列显示 `—`，并沿用估值表内的复核时点值）。表观 PE 不作定档依据：多数标的（周期顶部的存储股、被一次性投资收益抬高的科技股、亏损或战投期的平台股）必须按 §6.4 用归一化/中枢利润，换算过程写在 `fair_price_basis`。

**复核触发（§7 的海外适配）**：海外标的没有东财预告/快报/定期报告接口，§6.7.8/§6.7.9 的自动待复核名单不覆盖它们。改为：①各公司财报日已知者写入 `notes`，披露次日按 §7.3/§7.5.5 的 express 口径复核带与档；②重大事件（指引调整、并购、监管裁决、周期价格拐点）按 §7.4 触发。复核完成后更新 `valuation_reviewed_at` 与 `valuation_evidence_event`。带只由证据复核修改，档位每日随价自动重定——「价格改档、证据改带」在海外清单同样成立。

**日志**：逐票结论以 `workflow_stage = overseas_watchlist`、`decision_type = overseas_watch` 写入决策日志，`security_code` 为 `市场:代码`，`decision_result` 为 `质量档×估值档（策略，不可买）`。为避免每日刷新重复留痕，脚本**只记 `valuation_reviewed_at == as_of` 的行**（新增或改带当日各一行）；附表当日档位变化并入 `pool_price_refresh` 汇总行。

### 7.1 报告更新队列脚本接口

```bash
  --as-of YYYY-MM-DD \

```

`attention_class = garbage` 的公司不进入财报滚动更新队列。队列每个扫描日随 §9.1 步骤 0 重建（v1.16）——队列文件停留在旧 `as_of` 时，§7.3/§7.4 的新触发与 §7.5 冻结全部失效，属执行缺陷。

### 7.2 质量复核触发

```text
quality_cutoff = max(last_quality_review_date, 质量复核所用证据的 evidence_available_at)   # v1.26
如果 定期报告公告日 > quality_cutoff：
    进入质量复核队列（v1.18 公告日口径 + v1.26 证据日兜底）
如果 latest_report_date（报告期末） > quality_cutoff：
    进入质量复核队列（回退口径：披露物化文件缺失时兜底）
```

`last_quality_review_date` 取分层表 `reviewed_at_utc`；`evidence_available_at` 为该次质量复核所依据的最新财务资料公开可得日（公告日，非报告期末），新增于分层表输出字段（§5.8），**留空时自动退化为 v1.18 的纯复核日比较**，不影响历史行。

**为什么要证据日兜底（v1.26，2026-07-30）**：仅比较"公告日 vs 复核日"时，**当晚吸收次日戳披露的复核必然被判为欠账**——中报/年报常在盘后现于数据接口而公告日戳为次日，当日完成复核后 `reviewed_at_utc` 恒早于公告日，队列次日仍列该股。这与 §7.3 在 v1.18 修掉的是**同一个缺陷**，当时只改了估值侧、质量侧漏改。判例：宏发股份 2026-07-29 晚复核吸收 7/30 戳中报，7/30 队列仍列 `quality_only`（当日已按伪欠账留痕）；2026-07-30 东鹏饮料/顺络电子/乐鑫科技三只同日复核吸收 7/31 戳中报后**同一形态复现三次**，四行 `quality_only` 全为伪欠账。伪欠账不阻断买入（§7.5 只对 `valuation_review_needed` 冻结），但会淹没真实欠账、削弱队列的可信度，故按 §15 第 3 条先改本文件再重跑。

### 7.3 估值复核触发

```text
对 quality_tier in ["L1", "L2", "L3", "L4"]，以下任一公告日 > last_valuation_review_date 即进入估值复核队列：
    业绩预告公告日   （queue_reasons = forecast_after_last_valuation_review，v1.16）
    业绩快报公告日   （queue_reasons = express_report_after_last_valuation_review，v1.18）
    正式定期报告公告日（queue_reasons = report_disclosure_after_last_valuation_review，v1.18）
回退口径（披露物化文件缺失该股时兜底）：
    latest_report_date（报告期末） > last_valuation_review_date（queue_reasons = latest_report_after_last_valuation_review）
```

`last_valuation_review_date` 取估值表/核心池的 `valuation_reviewed_at`；该字段缺失时回退 `pool_as_of` 并在队列标注口径降级。公告日实际与 **max(估值时间, 估值证据日 `evidence_available_at`)** 比较（v1.18）：当晚复核吸收了次日戳披露的（`evidence_available_at`=该披露公告日）不再构成伪欠账（判例：洛阳钼业/陕西煤业/中矿资源 7/10 晚复核已含 7/11 戳预告，仍被 7/22 名单标记需批量确认；代价是同日戳的披露更正不触发，靠 §7.4 事件通道与 24 小时异动响应兜底）。三类公告日由队列脚本从披露物化文件（预告 §6.7.8、快报/正式报告 §6.7.9）确定性判定：**只要存在晚于估值时间的新披露即入队并冻结（§7.5），"是否大幅超/低预期"是复核的结论，不是入队的门槛**——门槛式措辞会让无人判断幅度时预告整体失流（睿创微纳 2026-07-20 判例）。触发一律用**公告日**而非报告期末（v1.18）：报告期末与复核日比较在"复核日落在报告期末之后、披露日之前"时必然漏触发，而 v1.16 预告季强制当日复核使该情形成为常态（判例：2026-07 中报预告季全池复核日 ≥7/10 晚于报告期末 6/30，若按期末口径，8 月披露的正式中报将全部漏检）。

### 7.4 事件复核触发

出现以下事件时立即进入事件复核队列：

1. 业绩预告、业绩快报或正式定期报告披露（L1-L4 一律经 §7.3 确定性入队，v1.16/v1.18；幅度是否重大由复核判定，不作入队门槛）。
2. 重大订单、重大客户认证、重大产品发布。
3. 重大并购、资产出售、控制权变更。
4. 交易所问询、监管处罚、审计异常。
5. 行业政策、技术路线、商品价格或竞争格局发生重大变化。
6. **强信号×催化当日复核义务（v1.02）**：池内标的当日信号分级=强且伴随官方级/公告级催化的，当日必须完成单票 express 估值复核（结论=是否调整**合理价区间**；档位由价格自动定档，§6.2.1.6）——结论可以是"带不变"，但必须显式复核并写决策日志，不得让带在催化持续发酵期间静止（判例：片仔癀 2026-07-13/15 基药目录+规划双催化连续三日在案、带自 7/11 静止，7/15 按旧带 hold_off 后 7/16 涨停）。预告类适用 §7.5.5 时效，其余催化类比照执行：当日完成复核的不产生跨日买入冻结。（原第 7/8 条价格越带/回落复核已由 §6.2.1.6 价格自动定档取代，v1.05 删除；v1.13 曾以"下行越档复核"部分恢复，v1.14 随单向限档一并撤销——价格类档位变化一律不触发复核义务。）

### 7.5 复核期买入冻结（buy_blocked）

估值复核触发（§7.3）或事件复核触发（§7.4）后、复核完成前，该股票处于 `review_pending` 状态并冻结新增买入：

1. 队列脚本对 `valuation_review_needed` 的股票输出 `buy_blocked = review_pending`。
2. 每日量价扫描读取更新队列（`--review-queue`），对池内处于冻结状态的股票即使出现有效信号也只输出 `buy_blocked_review_pending`，不列买入候选（§8.9/§11）。
3. 冻结不影响已有持仓的卖出扫描与风险监控。
4. 解除条件：完成质量/估值复核并更新 `valuation_reviewed_at` 与 `valuation_evidence_event` 后，重新生成更新队列即自动解除；复核结论若为高估/无法估值或降档，则按正常规则移出核心池。
5. 预告季时效（v20）：L1-L4名单内公司披露业绩预告/快报当晚，须在下一交易日开盘前完成单票 express 估值增量更新（含策略标签复检，如GARP拐点确认改挂D口径），使买入冻结不横跨信号日；boundary_pending 公司命中复核触发的，当日写入复核队列。**超期补做（v1.16）**：披露未被当晚发现的（漏检、非交易时段发起等），§9.1 步骤 0 检测到之时必须当场补做 express 复核，并在决策日志 `summary_reason` 注明超期原因；补做完成前该股保持 `review_pending` 冻结。复核义务与池内层无关——watch_only/excluded 行同样必须复核（冻结只关买入，带的时效性关系到档位、卖出许可与持仓监控）。

## 8. 阶段四：每日量价扫描

### 8.1 执行频率

每个A股交易日执行一次。标准口径为收盘后；作为 §9.1 组合流程的一部分在盘中发起时，按 §9.1 第 4 条盘中口径规则标注并收盘定型。

### 8.2 输入

1. `data/processed/a_share_core_valuation_pool.csv`（含 `watch_only` 仅观察层 v20 与 `excluded` 高估/无法估值仅观察层 v1.04——L1-L4 全量 worth_attention 统一扫描）
2. 前复权日线OHLCV（全部均线指标由日线计算，不需要周线/月线数据）
3. 行业指数和沪深300指数
4. 当日公告和重大新闻摘要

### 8.3 脚本接口

```bash
python3 scripts/screen_daily_volume_price_signals.py \
  --as-of YYYY-MM-DD \
  --input data/processed/a_share_core_valuation_pool.csv \
  --review-queue data/interim/a_share_report_update_queue.csv \
  --output-csv data/processed/daily_buy_candidates.csv \

```

`--review-queue` 可选：提供时对 `buy_blocked = review_pending` 的股票执行 §7.5 买入冻结；文件不存在时照常扫描并在输出头部标注未启用冻结。

### 8.4 基础指标

价格均线（全流程统一使用这一套日线级别均线，各规则只从组内取用；MA120≈半年线，MA150≈30周，MA250=年线≈12个月，A股一年约242-244个交易日）：

```text
MA5, MA10, MA20, MA60, MA120, MA250
```

组内分工：MA5-MA60 用于短中期趋势与信号（§8.6/§8.7），MA20 另兼反转/筑底态持仓的短期走坏判定（§14 v1.19），MA60/MA120 兼用于趋势态持仓的大趋势走坏判定（§14 趋势卖出），MA120 另用于强日线多头、长期趋势确认与持仓趋势参照分态的判态/毕业线（§14 v1.19），MA250 用于强日线多头、长期趋势确认与市场状态（§8.12）。每条均线的用途唯一且必要，不引入组外均线（MA150 随三档趋势保护线于 v1.12 退役）。

MACD：

```text
fast = 12
slow = 26
signal = 9
```

成交量指标：

```text
vol_ma5 = 5日平均成交量
vol_ma20 = 20日平均成交量
vol_ma60 = 60日平均成交量
vol_baseline_60_21 = 第60日至第21日前的平均成交量
day_vol_ratio_20 = 当日成交量 / 前20日平均成交量
vol_3d_ratio_20 = 近3日成交量合计 / (3 * 前20日平均成交量)
vol_5d_ratio_20 = 近5日成交量合计 / (5 * 前20日平均成交量)
vol_5d_ratio_baseline = 近5日平均成交量 / vol_baseline_60_21
vol_percentile_120 = 当日成交量在近120日成交量中的分位
amount_ma20 = 20日平均成交额
```

### 8.5 有效放量定义

满足任一条件即可认定为有效放量：

1. 单日放量：
   ```text
   day_vol_ratio_20 >= 1.8
   ```

2. 连续放量：
   ```text
   vol_3d_ratio_20 >= 1.5
   或 vol_5d_ratio_20 >= 1.4
   ```

3. 启动前基准放量：
   ```text
   vol_5d_ratio_baseline >= 1.6
   且近5日至少3日成交量 > vol_baseline_60_21 * 1.2
   ```

4. 持续堆量：
   ```text
   vol_ma5 > vol_ma20 > vol_ma60
   且 vol_ma5 / vol_ma60 >= 1.5
   ```

5. 高分位放量：
   ```text
   vol_percentile_120 >= 80
   且近5日价格涨幅 > 3%
   ```

6. 巨盘温和放量（v1.02）：
   ```text
   总市值 >= 2000亿
   且（day_vol_ratio_20 >= 1.3 或 vol_3d_ratio_20 >= 1.25）
   且当日收涨
   ```
   巨盘低波动股极少打出 1.8 倍以上量比，绝对量比门槛对其系统性失灵（判例：长江电力 2026-07-10/14 量比 1.2-1.5 的温和放量+短期新高，被绝对门槛与分位封顶双重压制）。本条属真实量能命中，命中即不属"仅分位单独命中"，不受 v31 分级封顶约束；市值阈值为 2026-07-17 初始校准，按 §12 回放修订。

说明：连续多日放量会抬高20日均量，因此不能只用当日成交量/20日均量判断是否放量，必须同时使用启动前基准量、3日/5日合计量和成交量分位。

### 8.6 趋势定义

日线多头：

```text
close > MA5 > MA10 > MA20 > MA60
```

强日线多头：

```text
close > MA5 > MA10 > MA20 > MA60 > MA120 > MA250
```

**中期多头排列（v1.21，§14 趋势态确认线）**：

```text
close > MA20 > MA60 > MA120
```

含义是中期均线组已完成由空转多的排列（而不只是价格一时越过某条线），用于 §14 判定一个仓位所依附的趋势结构是否已经是**成熟上升趋势**。单日价格穿越 MA120 不构成本条件：均线排列是慢变量，价格是快变量，只有慢变量转向才说明底部反转已经完成。上市不足 120 日无 MA120 者本条件恒不成立。

长期趋势确认（原"月线确认"日线化并精简：6月线→MA120、12月线→MA250；原10月线档在"满足其一"条件下几乎不独立起作用，v13起移除）：

```text
close > MA120
或 close > MA250
```

强长期趋势确认：

```text
close > MA120 > MA250
```

### 8.7 右侧信号

**核心原则**：只要出现**有效放量上涨**（满足 §8.5 有效放量且当日收涨），无论是否突破前高或关键均线，即列入 `buy_candidate`（仍受 §8.8 过度延伸过滤与 §11 风险过滤）。前高突破、均线突破、相对强度等不是入选的必要条件，而是**信号分级**的加分项。§8.7.1-§8.7.6、§8.7.8、§8.7.9 是**并列的独立触发形态**，各自满足即可触发 `buy_candidate`：其中 8.7.1/8.7.2/8.7.6/8.7.8 属于有效放量上涨的细分；8.7.3（缩量涨停）、8.7.4（连续上涨）、8.7.5（温和放量多头，量能可低于 §8.5 门槛）、8.7.9（底部企稳与 V 反计段，**无量口径**——底部企稳不硬性要求放量）不要求满足 §8.5 有效放量，是显式例外。8.7.7（相对强度确认）不独立触发，只作为信号分级的突破确认项。

**信号分级**（按放量 × 短期多头 × 突破确认三层递进给推荐等级）：

| 信号分级 | 条件 | 默认操作偏向 |
| --- | --- | --- |
| 强 | 有效放量上涨 + 短期多头（§8.6 日线多头或准多头） + 突破确认（§8.7.1/8.7.2/8.7.6 之一或 §8.7.7 相对强度确认） | 可建目标仓位1/3 |
| 中 | 有效放量上涨 + 短期多头，暂无突破确认 | 可小仓试探或等确认 |
| 弱 | 有效放量上涨，短期趋势未转多 | 等确认 |

三档均保留 `buy_candidate` 状态；分级只决定推荐强度与仓位偏向，弱势市场（§8.12）下各档偏向再下调一档。**买入资格另由 §8.13 入场阶段判定**（v1.02）：强/中/弱描述当日信号质量，入场阶段描述该层级×估值组合允许买入的最低右侧进度，两者正交。**封顶规则（v31）**：当有效放量仅由 §8.5 第 5 条「高分位放量」单独认定（其余 §8.5 条件均未命中）时，信号分级封顶「中」——低波动巨盘股的成交量分位容易越过 80 分位而无真实资金爆量（判例：长江电力 2026-07-10/13/14 量比始终 1.2-1.5 却三连输出"强"）；§8.5 第 6 条巨盘温和放量命中即属真实量能，不触发本封顶（v1.02）。

#### 8.7.1 放量突破前高

前高周期：

```text
60日、120日、250日、500日、750日
```

触发：

```text
close > 对应周期前高 * 1.005
且满足有效放量
且收盘价位于当日振幅上半区
```

收盘位置：

```text
close_location = (close - low) / (high - low)
要求 close_location >= 0.6
```

#### 8.7.2 放量突破关键均线 / 趋势启动

前高突破不是买入候选的唯一触发条件。高质量股票在主升早段可能先表现为放量突破关键均线、均线系统转多头和持续承接，然后才突破长期前高。

触发：

```text
close > MA20
且 close > MA60
且满足有效放量
且收盘价位于当日振幅上半区
且满足日线多头或准多头
```

准多头：

```text
close > MA5 > MA10 > MA20
且 close > MA60
且 MA20斜率走平或向上
```

强确认：

```text
日线多头
或 最近3-5个交易日内放量冲高回落后重新收强
或 个股相对行业指数和沪深300明显走强
```

收盘位置：

```text
close_location >= 0.6
```

适用说明：

1. 如果已突破前高，优先按`8.7.1 放量突破前高`处理。
2. 如果未突破前高，但放量突破MA20/MA60并形成准多头或多头排列，可进入`buy_candidate`或`wait_confirmation`。
3. 如果当日放量但收盘位置低于0.6，先进入`wait_confirmation`，等待后续1-5个交易日重新收强。
4. 如果价格仍低于MA120或MA250，优先级低于突破长期前高的信号，但不自动排除。

#### 8.7.3 缩量涨停

涨停阈值：

```text
主板普通股票：涨幅 >= 9.5%
创业板/科创板：涨幅 >= 19%
北交所：涨幅 >= 29%
ST股票：涨幅 >= 4.5%
```

缩量条件：

```text
当日成交量 <= vol_ma20 * 1.2
或 在前一日已经放量后，当日成交量 <= 前一日成交量 * 0.85
```

#### 8.7.4 连续上涨

触发：

```text
最近5日内至少4日上涨
且5日累计涨幅在8%-25%之间
且日线多头
且没有单日极端放量长上影
```

#### 8.7.5 温和放量多头

触发：

```text
日线多头
且20日涨幅在3%-20%之间
且vol_5d_ratio_20在1.1-1.8之间
且MACD在最近3个交易日内金叉
```

#### 8.7.6 平台突破后二次确认

触发：

```text
前期已放量突破
随后3-10个交易日横盘或缩量回踩
回踩不跌破突破平台2%以上
再次放量创新高
```

#### 8.7.7 相对强度确认

触发：

```text
个股近20日收益率 > 沪深300近20日收益率 + 8pct
且个股近20日收益率 > 所属行业指数近20日收益率 + 3pct
```

#### 8.7.8 底部/平台放量反转（v1.02）

捕捉"持续下跌后底部企稳、首次放量启动"的最早右侧事实（判例：片仔癀 2026-07-10 底部平台放量、7/13 底部连续放量，7/14 才达突破确认口径）。

触发（同时满足）：

```text
前置状态（满足其一）：
  平台期 = close 距 250 日最高收盘回撤 >= 25%，近 20 日未创 60 日收盘新低，且近 20 日收盘振幅（max/min - 1）<= 15%
  V 型反转 = 60 日内出现阶段低点后已收复 MA20，且低点距 250 日最高收盘回撤 >= 25%
当日：满足 §8.5 有效放量，收涨 >= 3%，close_location >= 0.6
```

连续强化：10 个交易日内第 2 次满足"当日"条件，记**底部连续放量**。

分级与阶段的关系：本形态成立当日短期趋势通常未转多，按三层分级规则多评"弱/中"；但其对 §8.13 入场阶段的贡献独立于分级——单次成立即达一段，底部连续放量即达二段。参数（回撤 25%、振幅 15%、涨幅 3%、10 日窗口）为 2026-07-17 初始校准，按 §12 回放与 §12.6 台账修订。

#### 8.7.9 底部企稳与 V 反计段（v1.06，无量口径）

**底部企稳不硬性要求放量**（判例：双汇发展 2026-07-01 平台大阳量比仅 1.24；茅台 2026-07-14 无量缓爬企稳）。本形态组不满足 §8.5 有效放量也可触发，是显式例外；触发即列 `buy_candidate` 并贡献 §8.13 段位。

前置状态：

```text
低位 = close 距 250 日最高收盘回撤 >= 15%，或 close < MA250
平台企稳 = 低位 且 近 20 日收盘振幅（max/min-1）<= 15% 且 近 20 日最低收盘 >= 60 日最低收盘 × 0.97（容忍小幅磨底假破位）
V 反语境 = 近 10 日最低收盘距 250 日最高收盘回撤 >= 25% 且 近 10 日内创过 60 日收盘新低（刚出坑，无需已收复均线）
```

触发形态（各自贡献段位）：

| 形态 | 条件 | 段位 | 判例 |
| --- | --- | --- | --- |
| a 平台企稳大阳 | 平台内 当日涨幅 >= 2.5% 且收位 >= 0.6 且 close > MA5（量能不限） | 一段 | 双汇 7/1（+3.66%、量比1.24）；茅台 7/15（+2.98%、量比1.54） |
| b 平台温和转强 | 平台内 MA5 > MA10、连续 3 日收盘 > MA5、近 5 日累涨 >= 1.5% | 一段 | 茅台 7/14 |
| c V 反启动阳线 | V 反语境内 当日涨幅 >= 3% 且量比 >= 1.3（收位不作硬性） | 一段 | 比亚迪 7/2（+3.61%、量比1.88、收位仅0.44） |
| d 平台上沿新高 | 平台内 收盘创近 20 日收盘新高（量能不限） | 二段 | 茅台 7/15、双汇 7/15 |

参数（15%/25% 回撤、0.97 容忍、2.5%/3% 涨幅、1.3 量比、20 日窗）按 2026-07-17 三判例校准（双汇 7/1 提醒 7/2-7/9 建仓、比亚迪 7/2 提醒 7/6-7/9 建仓、茅台 7/14 企稳 7/15 强势确认），修订先改本文件并经 §12 回放复验。

**脚本实现范围（v1.06 同步）**：8.7.0 放量上涨、8.7.1-8.7.5、8.7.8、8.7.9（企稳/V反计段）、§8.5 全部量能条件（含第 6 条巨盘温和放量，总市值=池 CSV `total_market_cap_bn` 按现价折算）、§8.13 入场阶段与延续（`entry_stage`/`entry_stage_today`/`stage_required`/`stage_met`，弱势市 +1 段）与 §6.2.1.6 档位价格自动定档（`valuation_tier_effective`/`band_position`）均由 `screen_daily_volume_price_signals.py` 判定；8.7.6 平台二次确认与 8.7.7 相对强度确认需要突破历史状态与行业指数数据，仍由人工/大模型在 §10 核对时判定。

### 8.8 过度延伸过滤

满足任一条件时，不直接列为买入候选，改为`wait_pullback`：

```text
close / MA20 - 1 > 25%
或 近5日涨幅 > 30%
或 近20日涨幅 > 60%
```

例外：

1. 同日或近期有明确财报、订单、客户认证、政策或产品催化。
2. 盈利预测出现重大上修。
3. 回踩平台不破后再次放量突破。

### 8.9 买入候选状态

| 状态 | 定义 |
| --- | --- |
| `buy_candidate` | 业务质量合格、估值未过度透支、出现有效放量上涨（无论是否破前高，含 §8.7 各右侧形态），并按 §8.7 信号分级标注 强/中/弱 |
| `wait_pullback` | 趋势强，但短期涨幅过大，等待回踩20日线或平台不破 |
| `wait_confirmation` | 单日异动明显，但收盘位置、持续承接或后续收强不足 |
| `wait_breakout` | 业务和估值合格，但尚未出现有效放量上涨 |
| `wait_repair` | 估值和业务合格，但跌破60日线或年线（MA250）未修复 |
| `liquidity_filtered` | 出现买入信号但 `amount_ma20` 低于流动性门槛（§11），不列为买入候选，仅提示 |
| `buy_blocked_review_pending` | 处于 §7.5 复核期买入冻结（财报/事件复核未完成），即使有有效信号也不列买入候选，仅提示 |
| `signal_watch_only` | 当日价格定档后未过 §6.2.1 矩阵的组合（含高估/无法估值）出现有效量价触发：可见不可买（v1.02 事件通道关闭，无当日直买例外），触发即走个人体系§9.4的24小时异动响应与§7.4事件复核（强信号×催化命中 §7.4 第 6 条当日 express 义务）；档位随价格自动刷新（§6.2.1.6），价格回落使组合过矩阵后自动恢复买入候选资格 |
| `inactive_watch` | 仍在核心估值合格池中，但无买入信号 |
| `remove_watch` | 业务thesis或估值基础被证伪 |

### 8.10 买入候选优先级

| 优先级 | 条件 |
| --- | --- |
| S | L1，低估/较低估/中性，放量突破120日以上前高，日线多头，长期趋势确认（§8.6），相对强度确认 |
| A | L1/L2，低估/较低估/中性，出现放量突破前高、放量突破关键均线、温和放量多头或平台后二次确认 |
| B | L1，较高估，但盈利预测持续上修且出现强右侧信号 |
| C | L3（战术层，低估/较低估）达到 §8.13 入场阶段：战术候选，必须先经 §10 闸门人工复核 |
| D | L4（战术层，仅低估）达到 §8.13 四段：极小战术候选，必须先经 §10 闸门人工复核，默认操作偏向下调一档 |

当日档位未过矩阵的组合不参与 S/A/B/C/D 定级与 §8.11 强势跟踪；`signal_watch_only` 每次触发走一次24小时异动响应，人工核对仅对信号分级强/中执行，弱级仅留痕（v20）。定级所用估值档一律为当日自动定档（§6.2.1.6）。

说明：S/A/B/C/D 优先级是"质量×估值"维度，§8.7 信号分级（强/中/弱）是"信号强度"维度，两者正交、输出时并列。仅满足有效放量上涨、未突破前高或关键均线的，仍为 `buy_candidate`（信号分级=中或弱），按 §8.11 的中短期量价强势定级排序。脚本的 S 级判定含前高突破、日线多头、长期趋势确认三项；相对强度确认暂由人工在 §10 核对时补充判定。

### 8.11 买入候选的强势跟踪

`buy_candidate` 一旦产生，必须每个交易日实时跟踪其股价与量价走势；强势程度**仅**由中期和短期量价走势判断，不引入基本面、前高位置等其它维度。

- **短期量价（约 5-10 日）**：close 相对 MA5/MA10，5 日涨幅，vol_5d_ratio_20，近 5-10 日相对沪深300与行业指数的强弱。
- **中期量价（约 20-60 日）**：close 相对 MA20/MA60，20-60 日涨幅，量能趋势（vol_ma5/vol_ma20/vol_ma60 排列），近 20-60 日相对强度。

| 强势 | 含义 | 处理 |
| --- | --- | --- |
| `strong` | 中短期量价同向走强、量价配合健康 | 维持买入候选，按 §8.10 优先级 |
| `neutral` | 中短期走平或量价背离 | 保持观察，等待再次放量上涨 |
| `weakening` | 中短期转弱、放量下跌或缩量阴跌 | 降级，必要时移出买入候选 |

强势跟踪只用量价，不构成买入命令；买入前仍需 §10 人工核对。

#### 8.11.1 持续候选置顶提醒（v1.20）

**解决的问题是可见性，不是选股**。§8.7 分级（强/中/弱）是**单日**信号强度，§9.3 规定弱级只汇总只数、不逐股展开——于是"每天都合格、但每天都只到弱级"的标的在阅读版日志中长期不可见。判例：**特宝生物 2026-07-15 → 07-27 连续 8 个扫描日为 `buy_candidate`、段位 3/需3 全程达标、窗内 5 日产生新的段位触发，其中仅 7/20、7/21 因当日评中级被点名，其余 5 日只进计数**；用户在 07-27 建仓后回看才发现该股早已反复出现。

触发条件（全部满足，由 `screen_daily_volume_price_signals.py` 判定）：

```text
当日 signal_state = buy_candidate（已过 §6.2.1 矩阵）
且 stage_met = True
且 stage_met_days   >= 8   （近 10 个交易日中有效段位 >= 所需段位的天数：持续可买，非一日达标）
且 stage_trigger_days >= 4 （近 10 个交易日中产生新段位触发的天数：反复自我确认，非挂在一次旧触发上延续）
且 §8.11 强势 != weakening
```

组稿时再排除**当前持仓**（第一节已逐只可见）后，列入 §9.2 第二节的"持续候选"行，按 (`stage_trigger_days`, `stage_met_days`) 降序；超过 12 只时展示前 12、其余只计数。

参数（窗口 10 日、达标 8 日、新触发 4 日）为 2026-07-27 初始校准：在当日 261 只全池、81 只 `buy_candidate` 上命中 25 只（非持仓 18 只），特宝生物以"达标 8/10、新触发 5 日"入选；仅用连续候选日数不加新触发条件会命中 50 只（"阶段延续"会让大半个池子长期挂榜），故必须两项并用。按 §12 回放与 §12.6 台账修订，修订先改本文件。

**本提醒不改变任何既有判定**：不改分级、不改 §8.10 优先级、不改 §8.13 所需阶段、不改 §6.2.1 买入资格；命中不等于建议买入，仍须过 §8.8/§11/§10 全部关卡。

### 8.12 市场状态判定

每日扫描时由脚本用沪深300指数计算市场状态，写入 `daily_buy_candidates.csv` 的 `market_state` 字段并随运行输出打印，扫描日志条目头部（§9.2）照抄：

```text
强势 = 沪深300收盘 > MA250 且 MA250 较20日前上行
弱势 = 沪深300收盘 < MA250 且 MA250 较20日前下行
震荡 = 其余情形
```

市场状态不改变信号分级本身，只调整默认操作偏向：弱势市场下各档偏向下调一档（强→可小仓试探或等确认，中/弱→等确认）。总仓位控制遵循个人投资体系 §3。

### 8.13 分层×估值的右侧入场阶段（v1.02）

**全流程仍然拒绝左侧买入**：任何买入都要求已出现右侧量价事实，最低门槛是一段（首根有效放量大阳线）。本节把"右侧确认到什么程度才能买"按质量层级×低估程度分档——越高质量、越低估的组合允许越早入场，越平庸、越接近合理价的组合要求越充分的确认。这取代了"所有组合统一等强信号"的旧口径，用于修复"确认完成时赔率已耗尽"的结构性死区（判例：片仔癀 7/10 一段 → 7/13 二段 → 7/14 四段，旧口径下 7/14 前不可买）。

| 入场阶段 | 达成方式（满足其一；高段自动覆盖低段） |
| --- | --- |
| 一段·首信号 | §8.7.8 底部/平台放量反转单次成立；或 §8.7.9 a 平台企稳大阳 / b 平台温和转强 / c V反启动阳线（无量口径） |
| 二段·初步承接 | §8.7.8 底部连续放量；§8.7.9 d 平台上沿新高；或**承接升段**（一段触发后收盘未破触发日最低价，见执行规则 5） |
| 三段·趋势反转确认 | 连续 3 个交易日放量上涨（vol_3d_ratio_20 ≥ 1.5 且 3 日均收涨）；§8.6 日线多头/准多头成立 + 当日有效放量上涨；或**趋势里程碑**（触发有效期内收盘收复 MA20 且高于触发日收盘，见执行规则 5） |
| 四段·突破确认 | §8.7 信号分级=强口径（有效放量 + 短期多头 + 突破确认，仅分位量不计） |

各组合所需最低阶段见 §6.2.1 矩阵末列。执行规则：

1. 阶段是**信号侧最低要求**，不是买入命令：达标后仍须过 §8.8 过度延伸过滤、§11 风险过滤与 §10 闸门（含 §6.2.1 执行说明 6 档位价格刷新）。
2. 锚定行来自 2026-07-17 用户决定与判例：L1×低估=一段、L3×较低估=三段、**L2×中性=三段**（比亚迪 V 反判例：7/2 提醒、7/6-7/9 建仓窗口须达标，v1.06 由四段下调）；其余映射为锚点间的单调内插初始校准，按 §12 回放与 §12.6 台账修订，修订先改本文件。
3. 弱势市场（§8.12）下所需阶段整体上调一段；四段组合改按 §8.7.6 平台二次确认口径执行。
4. 一/二段入场的止损锚定启动结构（启动阳线低点或平台下沿，daily 档口径），建仓时将该锚写入持仓清单 `launch_platform_price`；跌回启动结构即右侧事实失效（即 §14 反转态走坏·结构档，触发趋势卖出许可），按 §14 退出规则处理，不得以"低估"为由转为无止损左侧仓（个人体系 §17.3 R4/R6）。
5. **阶段延续与承接（v1.06，取代"当日口径"）**：股票不可能天天放量大涨，放量大涨后的缩量整理是信号的**延续**而非转弱——
   - 有效段位 = 近 **5 个交易日**内达到的最高段位；任何新触发刷新有效期（承接锚保持首次触发日的最低价/收盘价口径）。
   - 承接升段：一段触发后，只要后续收盘不破触发日最低价，即升二段（判例：双汇 7/1 大阳 → 7/2 缩量平盘维持强势）。
   - 趋势里程碑：触发有效期内收盘收复 MA20 且高于触发日收盘 → 升三段（判例：比亚迪 7/3、茅台 7/15）。
   - 失效归零：收盘跌破触发日最低价；或放量下跌（量比 ≥ 1.5 且当日跌幅 ≥ 3%）；或超过 5 个交易日无新触发（判例：茅台 7/3 假启动于 7/9 破触发日低点归零）。
   - 扫描输出 `entry_stage`（有效段）与 `entry_stage_today`（当日新达段）两列；报告对无当日触发但有效段仍在的标注"(延续)"。同一计段函数附带输出近 10 日的 `stage_met_days` 与 `stage_trigger_days`，供 §8.11.1 持续候选提醒使用（v1.20）。

## 9. 每日例行扫描与输出

### 9.1 组合流程（每交易日一次，支持盘中发起）

用户发起"当日的每日扫描"时按固定顺序执行——**先披露同步，再先持仓、后池**：

0. **披露同步（v1.16；v1.18 扩至全部三类披露，先于两项扫描）**：先刷新两个披露物化文件，再重建报告更新队列——`python3 scripts/fetch_a_share_earnings_forecasts.py`（业绩预告）→ `python3 scripts/fetch_a_share_report_disclosures.py`（**正式定期报告 + 业绩快报**，§6.7.9）→ `python3 scripts/build_report_update_queue.py --market A_SHARE --as-of 当日`（两个抓取脚本 `--report-date` 缺省自动取最近一个已结束的季度报告期末；接口不可用时沿用旧文件，并在当日条目显式标注其检索日）。本步保证**凡披露了定期报告、业绩快报或业绩预告的池内/名单内股票当日即被追踪**：公告日晚于其估值时间的自动进入 §6.7.8/§6.7.9 待复核名单与 §7.5 买入冻结，并按 §7.5.5 当日完成 express 估值复核、当日更新估值信息（合理价区间 + 估值时间/估值事件）。队列文件 `as_of` 早于扫描日即为执行缺陷，须当场补跑。判例：睿创微纳 2026-07-20 盘后中报预增 +242%-270%（公告日 7/21），因预告文件停在 7/17、队列停在 7/10、7/21 弱级触发不核公告，三层全部漏检，直至 7/22 用户指出——本步即为此增设；华润三九 7/15、大族激光 7/21（+163%）H1 业绩快报在仅预告抓取下不可见，直至 7/22 补建披露物化——v1.18 即为此扩容。
1. **持仓健康度**：运行 `scan_holdings_sell_signals.py --as-of 当日`（读取账户快照），按 §14 状态字与 §9.2 红黄绿映射汇总每只持仓的健康度、当日量价特征与需要的动作。
2. **池内关注对象**：运行 `screen_daily_volume_price_signals.py --as-of 当日 --review-queue data/interim/a_share_report_update_queue.csv`，从输出中筛选 `buy_candidate`（按 §8.10 优先级 × §8.7 信号分级排序，标注 §8.13 入场阶段与带内位置）与 `signal_watch_only`，逐只写出关注原因；另按 §8.11.1 取 `persistent_candidate = True` 且非持仓者，单列"持续候选"行（弱级不展开的可见性补丁，v1.20）。随后运行 `build_a_share_core_valuation_pool.py --md-only --quotes fetch --as-of 当日` 刷新池阅读版（现价/空间/PE/PB/价格自动定档，§6.7.7）；刷新汇总给出的**当日档位变化名单**写入扫描报告第二节。**候选判定纯量价×档位口径（v1.02）**：账户杠杆、仓位包络、资金状态、既有持仓结构一律不参与候选的判定、分级、阶段与排序；执行侧约束（包络、棘轮、买入时间窗）只在 §10 闸门与下单环节核对，扫描第二节不得出现基于账户状态的冻结、降序或"仅记录不执行"结论。
3. **输出**：按 §9.2 格式先以回复形式给出，再将同一内容置顶写入 §9.4 扫描日志。两张 CSV 与决策日志照常由脚本生成（v25 起脚本不再生成独立 tracker 阅读版）；扫描日志是唯一每日阅读文件，不替代机器记录。
4. **盘中口径（未收盘发起时）**：
   - 头部标注"盘中截至HH:MM"；当日 bar 为未完成 bar，"收盘价"实为最新价。
   - 量比类指标按已成交量计算，属系统性低估的**下限口径**；可附"已成交量 ÷ 已交易时间占比"的线性外推估算作参考，须标注为估算。
   - 信号成立与否的正式判定以收盘数据为准，盘中判定一律标注"待收盘定型"。例外：割肉价触及本就以当日价判定（§14 Tier-0），盘中触及即为最终动作信号，不等收盘。
   - **收盘定型**：仅对盘中"已触发或接近触发"的标的（割肉价、强/中级信号、大趋势走坏临界）在收盘后复核；结论有实质变化的，在当日日志条目内追加"收盘更新："行，无变化不追加，不要求全池重扫。
5. 同一交易日重复发起（如盘中一次、收盘后一次）时，更新当日日志条目，不新增第二条。

| 黄（预警/复核） | `risk_alert`、`trend_sell_allowed`、`valuation_sell_eligible`、估值档位恶化；现价贴近割肉价的提示（提示口径，不构成动作阈值） |
| 绿（健康） | `hold`；`add_eligible` 归绿但须单独点名资格 |

**不得进入黄组的项（v1.21）**：单笔风险的持仓监控值（已退役，§14 风险预警 4）、因股价上涨被动越过结构上限或偏离建仓档位金额的持仓（§13 第 8 条被动口径）。此类标的只要未触发 §14 卖出许可与其余预警，一律归绿；**上涨本身不是风险事件，不得以任何形式在健康度表内表述为警告或减仓建议**。

关注原因必须落在可核对的触发形态与数据上（§8.5/§8.7 术语与量价指标），不得写"感觉强势"类模糊描述；含当日催化的须注明信源等级（公告 / 权威研报 / 媒体报道）。

### 9.3 机器明细（CSV 口径，v25）

原量价/持仓两份 tracker 阅读版自 v25 退役，脚本只写 CSV 与决策日志；逐股全量明细以两张每日 CSV 为准：

- `daily_buy_candidates.csv`：池内全部扫描对象逐行，含 `signal_state`、`priority`、`signal_grade`、`entry_stage`/`stage_required`/`stage_met`（§8.13）、`stage_met_days`/`stage_trigger_days`/`persistent_candidate`（§8.11.1 持续候选，v1.20）、`valuation_tier_effective`/`band_position`/`band_top_flag`（§6.2.1.6 价格刷新）、`megacap_volume`（§8.5.6）、`action_bias`、`market_state` 与全部量价指标（§8.4）；`wait_*`、`inactive_watch`、`liquidity_filtered` 等非触发状态只留在 CSV，不进扫描日志。
- `daily_holdings_actions.csv`：每只持仓逐行，含 `holdings_action`、大趋势走坏判定、估值卖出资格与留底可卖金额、权重与单笔风险、估值档位刷新与带内位置（`effective_valuation_tier`/`band_position`，§6.2.1.6 口径，v1.15）。

扫描日志（§9.2）中对信号分级强/中的买入候选与触发动作的持仓，按下列要点行展开；弱级与无触发标的只汇总只数，不逐股展开：

```text
- 优先级×信号分级｜层级×估值档｜触发信号（§8.7 形态）｜量价要点｜相对强度｜当日催化（注明信源等级）｜风险｜操作偏向
```

### 9.4 扫描日志文件

- 路径：`data/processed/000_daily_scan_log.md`，**唯一的每日阅读输出**（v25 简并），**最新条目在最上**：新条目插入文件头部说明与分隔线之下、旧条目之上。
- 条目即 §9.2 格式块（强/中级候选与触发动作持仓按 §9.3 要点行展开），与当日回复内容一致；每交易日一条，重复发起时更新当日条目（§9.1 第 5 条）。
- 日志由大模型在完成组合流程后写入，属阅读汇总：机器记录以 `daily_buy_candidates.csv`、`daily_holdings_actions.csv` 与决策日志为准，日志本身不写决策日志行。

## 10. 买入前闸门（pretrade_decision）

每一笔实际买入对应 `data/processed/pretrade_decisions.csv` 一行，并写决策日志（`workflow_stage = pretrade_decision`）。闸门对齐个人投资体系 §9.1 通用买入清单（v1.8 起赔率项退役——估值对买入的约束由估值档位、合理价区间与 §6.2.1 矩阵在池层承担，闸门不再重复估值拦截）。

**闸门分两类项，约束力不同（v1.24，2026-07-30 用户决定）**：

- **要素项（硬前置）**：可由当日扫描数据与成交明细**客观核验**的条件，见 §10.1「要素项」。**任一不达标即不得建仓**；已成交的判 `off_system` 并进入 §15.1 留痕。（割肉价自 v1.25 起不在此列，按 §14 单独处理——见 §10.1 末注。）
- **研究档案项（限期义务）**：需要主观判断与文字组织的研究深度条目，见 §10.1「研究档案项」。**不构成建仓前置**，但属限期义务——未补齐期间该仓按 §14 定级 `pending_adjustment`、**禁止加仓**（轻仓升重仓须先补齐），每日扫描列入待办直至闭环。

设计理由（v1.24）：原口径要求全部 15 项在**下单前**齐备，否则一律判 `off_system`。用户的实际决策方式是"根据每日扫描的信号强弱与该股估值高低自行决策，不再二次询问模型"——这本身就是本流程的核心逻辑（§8.7 分级 × §6.2.1 矩阵），但在原口径下**任何盘后回报的成交都必然是 `off_system`**（前置记录按定义无法事后补成前置），使该标签丧失全部鉴别力。判例：2026-07-30 五粮液（A×强、四段达标、矩阵通过、割肉价 2.46×ATR20）与 2026-07-29 高德红外（C×弱级「等确认」偏向下入场、割肉价 0.24×ATR20 为账户最窄、与在持睿创微纳红外链隐藏 beta 重叠）拿到**同一个 `off_system` 标签**，前者次日仍在带内持有、后者次日即被止损出场——标签未能区分二者，等于没有预警。故将鉴别力集中到可核验的要素项上。

### 10.1 闸门清单（要素项硬前置 / 研究档案项限期义务）

**编号沿用 v20 以来的 1-15，不重排**（历史决策日志与扫描条目按编号引用）；每项前标注所属类别。

**要素项（硬前置，7 项：1、5、7、11、12、13、14）**——可由当日 `daily_buy_candidates.csv`、持仓清单与成交明细客观核验，任一不达标不得建仓（第 7 项自 v1.25 起只含"仓位档已设定"，割肉价另按 §14 处理）：

1. **【要素】** 已进入观察池且**当日价格定档后过 §6.2.1 矩阵**（§6.2.1.6 自动定档口径；L1×较高估另核 §6.6 上修/催化条件）、不处于 §7.5 买入冻结。
5. **【要素】** 已达到该组合的右侧入场阶段（§8.13，引用当日 `daily_buy_candidates.csv` 信号与阶段判定）；全流程拒绝左侧买入——无右侧信号或未达段位一律不得建仓（v1.02 起"极度低估且有催化剂"左侧通道删除）。**弱级信号叠加 `action_bias = 等确认` 时视为未达标**（v1.24；判例：高德红外 2026-07-29 于 C×弱级「等确认」偏向下入场，次日即 Tier-0 出场）。
7. **【要素】** 已设定仓位档（§13 重仓/轻仓二档，由用户定档）。**割肉价不属要素项（v1.25，2026-07-30 用户决定）**——建仓当时是否已给出 `stop_loss_price` 不作为"是否按流程操作"的判据，实测全部 17 只持仓的补定间隔为 **0-1 个交易日**（7/17 批建仓次日 7/20 补齐，7/22、7/23、7/27、7/29、7/30 各批均当日补齐），把这一量级的登记时滞判为要素缺失会重演"标签失去鉴别力"的老问题。缺失割肉价按 §14「割肉价缺失」条款处理：**该仓无 Tier-0 保护、每日扫描置顶提示、补定前禁止加仓**（见 §10.1 末注与 §14）。
11. **【要素】** 已核对买入后组合暴露：单票、产业链、大行业上限（§13 第 8 条主动口径按成交后预计占比校验），以及与现有持仓共享的隐藏 beta。
12. **【要素】** 单笔风险校验通过：建仓金额 × 止损距离 ≤ 账户净资产 1.5%（§13 第 6 条）。
13. **【要素】** 当日公告事实核对：是否有真实催化；是否存在澄清公告、监管问询、减持、解禁、融资、财务异常。**本项允许当日盘后补核闭环**（扫描第二节/纪律事件段已逐日执行），补核通过不影响要素齐全判定。
14. **【要素】** 股价未过度延伸（§8.8）。

**研究档案项（限期义务，8 项：2、3、4、6、8、9、10、15）**——不构成建仓前置；未补齐期间该仓 `pending_adjustment`、**禁止加仓**，每日扫描列待办：

2. **【档案】** 已完成研究卡片（引用决策日志/分层/估值结论的 `decision_id` 或文件位置）。
3. **【档案】** thesis 清晰（一句话可复述）。**本项最低成本，建议成交回报时一并给出。**
4. **【档案】** 已写 bear/base/bull 三情景，且完成反向预期拆解（市场已定价什么、预期差在哪）。
6. **【档案】** 已写明证伪条件（什么情况证明自己错了）。
8. **【档案】** 已设定加仓、减仓、清仓条件。
9. **【档案】** 已完成催化剂地图：每条写明具体事件、预计时点、影响程度、是否已被定价；写不出可追踪、可验证催化剂的，重新评估买入逻辑。
10. **【档案】** 已对前 2-3 个高概率高影响风险写好预设应对（"触发条件 -> 动作"），并入持仓清单的 `bear_case` 与 `exit_conditions`。
15. **【档案】** 同行业是否存在更强替代标的。**其暴露维度（与在持仓的隐藏 beta 重叠）已由第 11 项要素承担**；本项只管"是否选了同业中更弱的那只"这一判断。

> **两类项的分界**：要素项的共同特征是**不达标会直接放大本次交易的下行**（越矩阵、未达段位、超暴露、超单笔风险、踩公告雷、追高延伸）；研究档案项的价值在于**事后可追责与防叙事漂移**（R6），缺失不改变本笔的风险敞口，但会让后续的"thesis 是否已被证伪"无从判断——因此设为限期义务而非前置，并以禁止加仓作为约束力。

> **割肉价缺失的处理（v1.25，第三类：既非要素项也非研究档案项）**：割肉价是本体系**唯一的无条件退出硬底**，其重要性不因不列入要素项而降低——改变的只是"缺失是否等于未按流程操作"这一**判据归属**。缺失时按 §14 处理，三项约束同时生效：
>
> 1. **该仓无 Tier-0 保护**——补定前只有硬证伪（§14 卖出许可第 2 类）可强制清仓，趋势卖出与估值卖出均为许可而非指令，即该仓在补定前实际处于"无机械止损"状态；
> 2. **每日扫描置顶提示**至补定为止（§14 建仓期状态第 2/6 条既有机制，不新增）；
> 3. **补定前禁止加仓**（v1.25 新增，与研究档案项同构）——不得在无止损的仓位上放大暴露。
>
> `pretrade_decisions.csv` 以 `stop_loss_price` 空缺 + `research_due_note` 记明补定义务留痕；合规判定（`compliant`/`off_system`）不因该项空缺而降级。

### 10.3 成交回写（execution_record）

`approved` / `compliant` / `off_system` 项下实际成交的，必须当日：① 将持仓写入 `a_share_holdings.csv`（含 `stop_loss_price`、`build_amount_cny`、bear case、退出条件）；② 向决策日志追加 `workflow_stage = execution_record` 一行，记录成交价、股数、金额与对应 `pretrade_id`。未成交或放弃的，在决策日志记录原因。卖出执行同样回写持仓并记 `execution_record`。

### 10.4 全量记录与合规判定（v1.24 重写；原 v20「全量前置记录」口径撤销）

**取消"下单前必须已存在 pretrade 行"的形式要求。** 用户的常态操作是依据每日扫描的信号分级与该股当日估值档位自主决策、不再二次询问模型；原口径下这类成交无论质量高低一律判 `off_system`，标签因此丧失鉴别力（理由与判例见 §10 开头）。改为：

1. **每笔买入仍有且只有一行记录**（审计不放松），但记录**可在成交后补写**，不再因"事后补记"本身而降级。
2. **合规判定看要素项，不看记录时序**：成交后按 §10.1 要素项 7 项逐项核验——全部达标记 `compliant`（**按流程买入**）；任一不达标或无法核验记 `off_system`（**未按流程操作**），后者按 §15.1 留痕并在当日扫描条目置顶提示。下单前即完成全 15 项的仍记 `approved`。
3. **研究档案项转限期义务**：`compliant` 与 `off_system` 均须在 `research_items_pending` 列出未齐项。未补齐期间该仓按 §14 定级 `pending_adjustment`、**禁止加仓**（轻仓升重仓须先补齐全部档案项），每日扫描第三节列待办直至闭环。补齐后按 §14 复核可转 `qualified`。
4. **月度统计口径同步**（原"体系内 vs 体系外收益差"因分母恒为零而失效）：改为对比 **`approved`+`compliant`** 与 **`off_system`** 两组买入的 5/20 日与持有期收益，并单列"研究档案长期未补齐"仓位的表现，作为流程改进依据（与 §12.6 第 5 组一并复盘）。
5. **要素项无法核验时的处理**：核验所需数据缺失（如未提供成交价/股数、当日扫描未覆盖该股）一律**按不达标计** `off_system`，不得因"无法确证"而默认通过——这与 §15 第 7 条撤销时间窗的理由方向一致：**不可核验的条件不该产生合规结论**，要么可核验并硬性执行，要么不作为合规项存在。

## 11. 固定风险过滤器

以下股票不进入每日买入候选：

1. 当日价格定档（§6.2.1.6）后未过 §6.2.1 矩阵的组合（含高估/无法估值）与池外股票：量价信号仅留痕并走复核（§8.9 `signal_watch_only`），不列买入候选。
2. 估值档位为高估或无法估值。
3. 当前业务thesis被证伪。
4. 财务造假、审计异常、控股股东资金占用、重大治理风险。
5. 当日极端放量长上影且未收在高位。
6. 连续暴涨后远离20日线，且无明确业绩或订单上修。
7. 只因题材、小作文、传闻上涨，缺少公告、财报、订单、客户验证或权威研报支持。
8. 20日均成交额 `amount_ma20` 低于5000万元：流动性不足，脚本判定后输出 `liquidity_filtered`，不列入买入候选，仅提示。
9. 处于 §7.5 复核期买入冻结（`review_pending`）：财报或重大事件复核未完成前不列入买入候选，输出 `buy_blocked_review_pending`。

## 12. 历史回放校准

### 12.1 校准目的

在脚本正式作为每日流程使用前，必须验证该流程能识别历史上的高质量右侧启动机会。

### 12.2 外部回放案例

具体回放案例不写入本流程文件。回放案例应作为外部验证集单独维护，避免把用于校准的历史样本固化为流程规则。

每个外部回放案例至少记录：

1. 回放股票代码。
2. 回放日期。
3. 当时已公开的公司资料、财报、公告、研报和行业数据。
4. 当时已发生的价格和成交量数据。
5. 该案例用于验证的流程环节：质量分层、估值排雷、量价触发或卖出规则。
6. 成功标准。

### 12.3 回放脚本接口

```bash
python3 scripts/backtest_signal_replay.py \
  --as-of YYYY-MM-DD \
  --symbols CODE1,CODE2 \
  --workflow-version a-share-selection-operation-v1 \
  --input data/processed/a_share_core_valuation_pool.csv \
  --output data/interim/replay_external_validation_YYYYMMDD.csv
```

说明：`backtest_signal_replay.py` 复用每日量价扫描规则，用于验证历史日期前的价格和成交量信号。完整历史回放必须提供当时已公开信息构造的 `--input` 核心估值合格池；如果使用当前核心估值合格池，则只能验证价格信号，不能证明当时已经满足质量和估值前置条件。回放输入含 watch_only 层时，成功标准须区分「池内直接触发」与「watch_only 可见→复核→入池后触发」两种捕获路径（v20）。

### 12.4 回放数据限制

回放只能使用回放日期之前已经公开的信息：

1. 当时已经披露的年报、季报、公告、业绩预告。
2. 当时已经发布的权威研报。
3. 当时已经发生的成交量、价格、指数数据。
4. 当时已经可见的行业政策和产业数据。

不得使用回放日期之后的财报、研报、订单、股价走势或事后总结。

硬约束：回放使用的每条证据必须满足 `available_at <= 回放日`，其中 `available_at` 是公开可得日（公告日/发布日），**不是报告期末**。财务指标表以 `latest_report_notice_date`（公告日）为准；公告日缺失的数据不得直接用于回放，只能按“报告期末 + 法定披露时限”做保守估计并在回放记录中显式标注，或弃用该字段。

### 12.5 回放失败后的固定调整

如果任一外部回放案例失败，按以下规则调整流程：

1. 对产业链爆发股和战略能力型公司，降低当前利润在估值中的权重。
2. 对处于研发、产能爬坡、商业模式切换、行业爆发前夜的公司，强制使用归一化利润和未来2-3年正常化利润。
3. 对强技术壁垒、客户验证、产能瓶颈、行业渗透率快速提升的公司，即使当前PE偏高，也允许进入核心估值合格池。
4. 对低利润或亏损公司，必须区分“真实能力尚未兑现”和“商业模式无效”。
5. 如果公司通过质量分层和估值排雷，但量价未触发，则保持核心估值合格池，不强行买入。

## 13. 固定仓位动作

每日量价扫描只输出操作偏向：

| 操作偏向 | 执行含义 |

| 可建目标仓位1/3 | 允许建立计划仓位的第一笔 |

| 等确认 | 等待3-5个交易日持续承接 |
| 仅观察 | 不买入，只继续追踪 |
| 放弃 | 触发信号无效或估值/业务不合格 |

**仓位总规（v1.02，全流程唯一口径；个人体系 §2.1 同步）**——仓位数字只存在于本节，其他章节（§5.7、§6.2.1、§14）一律引用"重仓/轻仓"档名，不重复数字：

| 档 | 单票建仓金额 | 定档依据（由用户逐票决定） |
| --- | ---: | --- |
| **重仓** | 50 万元 | 低估深度、量价动能强度、未来上行空间、业绩增速、赔率等综合更优 |
| **轻仓** | 25 万元 | 其余通过筛选且达到 §8.13 入场阶段的标的 |

执行规则：

1. **二档口径（2026-07-17 用户设定）**：单票建仓金额只有重仓/轻仓两档（设定时净资产 N≈288 万），净资产达到 500 万前统一沿用，届时重新设定。**定档由用户逐票决定**：系统只提供层级×估值档、入场阶段、带内位置与量价事实，不代为定档。原核心/准核心/动量/观察四袖、只数上限与席位兼容规则（v1.00/v1.01）全部退役。
2. **准入前提**：任何买入须为池内常备可买档位组合、达到 §8.13 入场阶段并通过 §10 闸门；全流程拒绝左侧买入（原观察席"纯左侧无信号首笔"通道随四袖一并删除）。
3. **口径**：总仓位=持仓市值÷N=杠杆×100%（融资负债变动不扭曲单票口径）；行业/产业链等结构占比按**持仓市值**计（杠杆中性）；风险预算（单笔 1.5%N、回撤梯 -8%/-12%/-20%）按 N 计。
4. **仓位包络**（沿用）：常态中枢 **130%N**、浮动带 **100%-160%N**——低于 100%N 应寻找合格标的回补，高于 160%N 必须减仓/去杠杆；弱势市场（§8.12）禁用融资买入并向带内下沿收敛。总仓位 ≥130%N（杠杆 ≥1.3x）期间，个人体系 §17.3 R1 常态在线。包络与资金状态属**执行侧约束**：只决定是否/何时下单，不进入 §9 扫描的候选判定（v1.02）。
5. **杠杆风险提醒（v1.20，2026-07-27 用户书面确认后取代止损网格预算）**：原 Σ(仓位%N×止损距离) 设计 6%N/硬顶 8%N 预算**已撤销**（R7 冷静期 2026-07-20 提出 → 2026-07-27 满 5 个交易日并经用户书面确认，个人体系 §17.3 第 6 条程序完成；撤销理由见该节记录：持仓上涨而割肉价固定会使该指标机械走阔，把"浮盈回吐空间"计为"新增风险"，与单票风险已由割肉价逐票承担重复）。替代为**单一杠杆维度的风险提醒**，每日扫描输出、不构成自动动作：

   | 层 | 触发 | 提醒口径 |
   | --- | --- | --- |
   | **警告线** | 总仓位 > **160%N** | 每日扫描置顶警告并给出回带内所需减仓金额；包络本身仍是硬约束（见第 4 条"必须减仓/去杠杆"），本条只负责把缺口量化、逐日可见 |
   | **降至 130%N 提醒** | 满足任一：① §8.12 市场状态由强势转为**震荡或弱势**；② 出现**政策性风险事件**（流动性收紧、股市降杠杆/两融规则收紧、监管风险提示等，须公告/官方文件级）；③ **持仓性价比下降**——池内可买域收缩（低估+较低估标的数明显减少）或持仓中触发大趋势走坏（§14）的只数占比上升 | 提示向常态中枢 130%N 收敛，给出所需减仓金额与建议来源（按 §14 卖出许可与最弱仓排序） |
   | **降至 100%N 提醒** | 上述三项中**两项及以上同时成立**，或账户自峰值回撤触及 -8%（个人体系 §13.1 去杠杆线） | 提示向包络下沿 100%N 收敛 |

   执行说明：①三项判定中 ① 由脚本（§8.12）给出、③ 由当日扫描数据给出（可买域计数、`trend_deterioration` 只数），② 由大模型/人工按信源等级判定并注明；②③ 属**提醒而非阈值**，是否减仓、减多少由用户决定。②单笔风险 1.5%N 校验（第 6 条）、账户回撤梯 -8%/-12%/-20%（个人体系 §13.1）、融资棘轮（第 7 条）与结构上限（第 8 条）**均不受本次撤销影响，继续有效**——撤销的只是组合级止损距离加总这一项。
6. **一笔建仓**：机会确认后一笔建满所选档位金额，不强制分批；前置不可省——§10 闸门全项、割肉价给定、单笔风险校验：建仓金额×止损距离 ≤1.5%N（重仓 50 万在 N≈288 万下隐含止损距离 ≤8.6%；止损需更宽时降轻仓或放弃，不得直接放行）。本校验是**建仓时的一次性前置条件**，用建仓金额与建仓时止损距离计算；建仓后不转为持有期的监控指标，持仓期间不因股价上涨重算并预警（v1.21，见 §14 风险预警 4）。
7. **融资棘轮**：融资买入的仓位止损/退出后，回笼资金必须先偿还融资，不得循环滚入下一笔买入。
8. **结构上限**：同一产业链 ≤40%、同一大行业 ≤60%、单票绝对红线 30%（均按持仓市值）；build_amount 金额制已退役，持仓清单 `build_amount_cny` 记实际建仓金额。

   **主动/被动口径（v1.21）**——上述上限约束的是**主动增加的暴露**，不是价格上涨本身：

   | 情形 | 处理 |
   | --- | --- |
   | **主动越限**（新建仓或加仓后将越过任一上限） | **硬拦**：不得买入。§10 闸门第 11 项与本节加仓条件按**成交后**的预计占比校验，越限即 `hold_off`；口径不变、不放宽 |
   | **被动漂移越限**（既有持仓因上涨使占比越过上限） | **不预警、不建议减仓、不进入健康度红黄绿分组**；机器 CSV 保留 `weight_over_limit` 事实位供审计。约束只有两条：①**禁止再加仓**（不得主动扩大）；②每越过一个 10 个百分点台阶（30%→40%→50%…）做一次个人体系 §2.1「单票接近 30% 绝对红线」六项持有资格复核，通过即维持、无动作，不合格才进入处置讨论 |
   | 该票**同时**出现现档转较高估/高估，或大趋势走坏（§14） | 权重此时才作为**处置排序**输入（先减占比最大的），并按 §14 卖出许可执行 |

   理由：机械的"涨多了就减到上限内"与个人体系 §12「盈利后减仓与十倍股保护」直接冲突——§12.3 在 >+500% 明确"停止机械卖出，改用趋势和 thesis 保护"、10 倍时"thesis 未破时保留永久底仓"，§12.2 也要求止盈须先满足 thesis/估值/趋势类条件之一。持仓市值随股价上涨偏离建仓档位金额（重仓 50 万/轻仓 25 万）**同样不构成超限**——档位金额是建仓时的投入口径，不是持有期的目标市值。大赢家被逐日警告会制造恐慌并促成过早卖出，这是本体系明确要避免的失败模式；真实的下行保护由逐票 Tier-0 割肉价、账户回撤梯 -8%/-12%/-20% 与"禁止再加仓"共同承担，均未改动。

加仓（轻仓升重仓，一次性补足至 50 万）必须满足：

1. 买入后趋势继续成立（按 §14 趋势参照分态：趋势态=未触发大趋势走坏；反转/筑底态=启动结构未破且收盘 ≥ MA20，不以收复 MA60/MA120 为前提，v1.19）。
2. 回踩不破平台或均线。
3. 财报、订单、利润率、行业数据或盈利预测至少一项继续验证。
4. 当前估值仍未进入高估档。

退出全部遵循阶段五（§14）卖出许可：无条件清仓只由割肉价与硬证伪决定；现档较高估/高估允许估值卖出（留底原则，剩余市值原则上不低于建仓金额）；大趋势走坏（§14 分态口径：趋势态收盘跌破 MA60/MA120，反转态收盘跌破启动结构或 MA20）允许减仓乃至清仓；其余技术走弱信号（右侧失败跌回平台、高位放量滞涨后缩量阴跌等）只作风险预警。

### 建仓期状态（2026-07-12 用户声明，撤销前有效）

当前持仓并非按本流程建立。自 2026-07-12 起账户处于**建仓期**，持仓清单以 `position_status` 字段逐只定级，目标是向流程合规状态收敛：

| `position_status` | 含义 | 锁定期 | 割肉价 | 调整权限 |

### 输入

1. `data/processed/a_share_holdings.csv`：当前真实持仓，手工维护。
2. 前复权日线OHLCV（走坏判定按趋势参照分态用日线 MA20/MA60/MA120；判态与毕业需自首次建仓日以来的收盘序列；不需要周线/月线数据）。
3. 行业指数与沪深300指数。
4. `data/processed/a_share_core_valuation_pool.csv`：用于刷新持仓的最新估值档位。
5. `data/processed/a_share_workflow_decision_log.csv`：用于回看持仓的策略标签、bear case与退出条件。
6. 当日公告与重大新闻摘要。
7. `data/processed/portfolio_account_snapshot.csv`：账户净资产/总资产/融资负债与净值峰值，用于账户回撤状态、杠杆与担保比例预警。

### 持仓清单字段

`a_share_holdings.csv` 至少包含：

```text
security_code, security_name, strategy_tag, quality_tier, valuation_tier,
position_status, entry_date, build_amount_cny, initial_shares, cost_basis,
current_shares, stop_loss_price, cumulative_trim_pct,
launch_platform_price, thesis_summary, bear_case,
add_conditions, exit_conditions, last_review_date, notes
```

字段说明：

- `position_status`：建仓期定级（见本阶段开头「建仓期状态」）：`qualified` 定级合规；`pending_adjustment` 建仓期内待调整（两者割肉价口径一致，均 Tier-0）。建仓期结束后本字段统一为 `qualified` 或随条款移除。

- `build_amount_cny`：本次建仓投入金额，按“建仓金额规则”确定。
- `initial_shares`：建仓股数（台账记录；原盈利离场档位基准随 v1.12 退役）；`current_shares` 为当前剩余股数。
- `cost_basis`：建仓均价。
- `stop_loss_price`：割肉价，建仓时由用户给定的无条件清仓参考线；是否调整由用户决定（下调/取消命中个人体系 §17.3 R4，先走 §15.1 拦截）。
- `cumulative_trim_pct`：已累计卖出占 `initial_shares` 的百分比。

### 建仓金额规则

1. 单票建仓金额与总仓位一律按 §13 仓位总规执行（重仓/轻仓二档、130%N 中枢、100-160%N 包络），一笔建仓，原则上不持有现金。
2. 建仓前须通过 §10 买入前闸门与 1.5%（净资产口径）单笔风险校验。
3. 原 build_amount 金额制（25万起、总资产达 build_amount*20 翻倍）自 v20 退役；持仓清单 `build_amount_cny` 字段改记实际建仓金额，历史行含义不变。

### 割肉（止损）规则

1. 买入时必须在持仓清单写入 `stop_loss_price`（割肉价，由用户给定）。
2. 当日价 <= `stop_loss_price` 时，无条件清仓（Tier-0）；**当日或次日开盘执行，不得以“等待 1-3 日确认”延迟**。
3. 割肉价不做体系化维护（v1.11）：不设 MA120 等外部锚上限、体系不输出上调建议、不跟踪上调日期。用户上调（收紧）随时允许；下调或取消命中个人体系 §17.3 R4，先按 §15.1 拦截协议处理。
4. **建仓时未给出割肉价的处理（v1.25，2026-07-30 用户决定）**：登记时滞按实测为 0-1 个交易日，**不作为 §10 买入合规判据**（不进 §10.1 要素项，不因此判 `off_system`）。但补定前三项约束同时生效：①该仓**无 Tier-0 保护**——只有硬证伪可强制清仓，趋势/估值卖出仅为许可，即处于无机械止损状态；②**每日扫描置顶提示**至补定为止（本节「建仓期状态」第 2/6 条既有机制）；③**补定前禁止加仓**——不得在无止损的仓位上放大暴露。用户原述："在建仓时是否给出了割肉价其实并不本质，也并不关键，很多时候都是我忘记给出了，后续有时间或者闲下来会补充割肉价，因此这个问题不应当成为是否按照流程操作的重点。"

### 卖出许可（v1.12，2026-07-20 用户重设）

本节全量替代原 3 个月锁定期、退出优先级矩阵 Tier-2 与按浮盈档位的「盈利后离场规则」（+30%→10% 等累计卖出上限表，v1.12 退役）。卖出许可只有以下四类，此外不卖出——盈利本身既不是卖出理由，也不再限制卖出：

1. **割肉清仓（Tier-0，`stop_loss_sell`）**：当日价 <= 割肉价，无条件清仓，见「割肉（止损）规则」。
2. **硬证伪清仓（`forced_exit`，原 Tier-1 保留）**：① 一票否决：财务造假、控股股东资金占用、审计异常等确凿治理/财务问题；② 公司重大突发事件；③ 季报披露后利润严重不及预期；④ 经核实的结构性 thesis 证伪（核心大订单取消或重大客户流失被公告/权威信源确认、技术路线被颠覆致产品被实际替代、政策逻辑反转使 thesis 不再成立）。判定纪律不变：第④类必须以公告、监管文书或多个权威信源核实为准，“担心”“传闻”“股价下跌”不构成硬证伪，只作风险预警；大模型判定 + 卖出前人工核对后立即清仓。
3. **估值卖出（`valuation_sell_eligible`）**：持仓现档（§6.2.1.6 价格自动定档）为较高估或高估时允许卖出；**留底原则**——卖出后剩余持仓市值原则上不低于初始建仓金额（`build_amount_cny`，重仓 50 万/轻仓 25 万口径），即只收割建仓金额以上的增值部分；现档回到中性及以下即失去本许可。
4. **趋势卖出（`trend_sell_allowed`）**：大趋势走坏（按下节趋势参照分态判定，v1.19：趋势态=收盘跌破 MA60 或 MA120；反转/筑底态=收盘跌破启动结构锚或 MA20）允许减仓乃至清仓，不受留底约束；经卖出前人工核对后执行。

补充：账户级降风险（偿还融资、结构/包络收敛）所需的卖出属降风险方向，始终允许（§15.1 第 4 条），不以第 3/4 类触发为前提；上调割肉价随时允许（v1.11）。thesis 走弱未坐实（订单延迟、利润率未如期改善、竞争加剧、验证进度落后）与估值过热不再构成独立卖出通道，统一并入现档定档与风险预警。

### 除权除息处理

分红、送转、配股的除权除息日，必须在当日扫描前按除权除息因子机械调整持仓清单中的价格与股数字段：`stop_loss_price`、`cost_basis`、`launch_platform_price` 按因子调整；送转/配股同时调整 `initial_shares`、`current_shares`。该调整是价格口径换算，**不属于"下调割肉价"**；浮盈与建仓金额留底口径按调整后数值计算。K线使用前复权数据，未调整的绝对价格字段会在除权日引发误触发（现价机械下跳击穿割肉价）或浮盈失真。持仓清单为手工维护，调整由维护者完成，并在 `notes` 记录调整因子与日期。

### 大趋势走坏（趋势卖出的判定口径，v1.19 分态；v1.12 单一口径升级）

**持仓趋势参照分态**：走坏参照必须匹配该仓位所依附的趋势结构。底部反转/横盘筑底期建立的仓位（本体系 §8.7.8/§8.7.9 信号与一/二段入场天然产生此类仓位——触发前置本就要求距 250 日高点回撤 ≥15-25%）入场时收盘就低于 MA120，"跌破 MA60/MA120"自入场起恒为真、不含增量信息（判例：神火股份/国电南瑞/宁德时代 2026-07 建仓后底部结构走强当日仍被静态标注"趋势走坏"，2026-07-23 全组合 9/17 只黄标中多数属此类）；对这类仓位，有信息量的参照是**启动结构与短期趋势（MA20）**。成熟趋势中建立的仓位则相反：MA20 回踩属正常波动，MA60/MA120 破位才是趋势变质信号（v1.12 设计意图，对趋势态持仓继续成立）。

| 态 | 判态 | 走坏判定（触发 `trend_sell_allowed`） |
| --- | --- | --- |
| **趋势态** | 首次建仓日 §8.6 **中期多头排列**成立；或反转态毕业后 | 收盘 < MA60（60 日档）；收盘 < MA120（120 日档，提示更重）——原 v1.12 口径不变 |
| **反转/筑底态** | 首次建仓日中期多头排列不成立（含上市不足 120 日无 MA120 者） | **结构档**：收盘 < 启动结构锚（右侧事实失效，§8.13 执行规则 4，提示最重）；**短期档**：收盘 < MA20 |

执行细则：

1. **判态与毕业（v1.21 收紧毕业口径）**：以**首次建仓日**是否满足 §8.6 中期多头排列（`close > MA20 > MA60 > MA120`）判态（加仓不重判）；反转态自建仓后**任一交易日满足中期多头排列即毕业**转趋势态，毕业不可逆——此后再跌破 MA60/MA120 才是新信息，按趋势态口径判走坏。存量持仓按"自首次建仓日以来是否曾满足中期多头排列"初始化。

   原 v1.19 的毕业口径是"任一收盘 > 当日 MA120"，已于 v1.21 废止：**单日价格越过 MA120 只是快变量的一次穿越，不等于底部反转完成**。底部反转仓在冲高时会先站上 MA120（此时 MA20 < MA60 < MA120 仍是空头排列），据此立即转趋势态，则次日一根正常回调收盘落回 MA120 之下即触发"趋势走坏"，而此时价格可能仍高于 MA60、高于 MA20 数个百分点——这类警告不含增量信息，只制造噪声与恐慌（判例：2026-07-29 紫金矿业收 32.15、MA120 32.64 判 120 日档走坏，但价格高于 MA60 29.75 达 8.1%、高于 MA20 29.38 达 9.4%；同日宁德时代收 396.84、MA60 398.97 判 60 日档走坏，而价格高于启动结构锚 366.01 达 8.4%、高于 MA20 375.22 达 5.8%；小商品城当日仅因收盘 12.65 越过 MA120 12.42 即被判"毕业转趋势态"，其 MA20 10.79 < MA60 11.42 < MA120 12.42 仍是完整空头排列，反转显然尚未完成）。改用均线排列后，毕业当日必然满足 `close > MA20 > MA60 > MA120`，即毕业时与 MA60 之间天然留有缓冲，此后跌破 MA60 是价格从 MA20 上方实质下移的结果，走坏判定重新具备信息量。
2. **启动结构锚**：优先取持仓清单 `launch_platform_price`（建仓时按 §8.13 执行规则 4 记录启动阳线低点或平台下沿）；未记录的存量仓不单独输出结构档（结构保护并入 Tier-0 割肉价），仅短期档生效。
3. **反转态下收盘 < MA60/MA120 不输出走坏**（入场即低于，无新信息）；健康度分组（§9.2）随状态字自然联动——反转态标黄的理由只能是结构/MA20 档触发或其他预警，不得是静态的"低于 MA60/MA120"。
4. **许可性质不变**：这是卖出许可而非卖出指令，跌破只解锁减仓/清仓权限，是否执行、执行多少由用户决定（卖出前人工核对区分单日噪声与澄清公告，核对 3 的 1-3 日等待适用）；收盘站回对应参照线上方后许可自动失效。与割肉价的关系不变：割肉价是唯一的无条件清仓硬底，趋势走坏只给权限。
5. **档位轻重**：短期档（MA20）是反转期正常震荡内的低强度许可，单日跌破即给权限、提示口径最轻；结构档触发即右侧事实失效，不得以"低估"为由转为无止损左侧仓（个人体系 §17.3 R4/R6）。

原三档趋势保护线（daily/weekly/monthly = MA60/MA150/MA250，连续 N 日跌幅确认）与 `trend_protection_level` 字段、strategy_tag 映射自 v1.12 全部退役；v1.12 的单一 MA60/MA120 口径自 v1.19 起仅适用于趋势态持仓。

### 脚本接口

```bash
python3 scripts/scan_holdings_sell_signals.py \
  --as-of YYYY-MM-DD \
  --holdings data/processed/a_share_holdings.csv \
  --valuation-pool data/processed/a_share_core_valuation_pool.csv \
  --account-snapshot data/processed/portfolio_account_snapshot.csv \
  --output-csv data/processed/daily_holdings_actions.csv \
  --log-file data/processed/a_share_workflow_decision_log.csv
```

脚本 `scripts/scan_holdings_sell_signals.py` 负责确定性部分：割肉触及、大趋势走坏判定（趋势参照分态 v1.19：判态/毕业按自首次建仓日的收盘序列，趋势态对照 MA60/MA120、反转态对照启动结构锚与 MA20，输出 `trend_ref_state`）、估值卖出资格（现档较高估/高估判定与留底可卖金额，按池内合理价区间以 §6.2.1.6 口径现算）、建仓金额与单票权重、持仓估值档位刷新（对照核心池，档位恶化或已出池输出 `risk_alert`）、账户回撤状态与杠杆/担保预警（读取账户快照最新行）、单笔风险校验（权重×止损距离对净资产的比例，超 1.5% 输出风险提示）。硬证伪清仓由大模型判定。`--valuation-pool` 与 `--account-snapshot` 缺省使用固定产物路径，文件缺失时降级运行并在输出头部标注。

### 脚本可判定的卖出与风险触发

按以下优先级处理每个持仓：

1. 硬证伪离场（最高优先级）：卖出许可第 2 类由大模型判定成立 → `forced_exit`，立即清仓。
2. 割肉清仓（无条件，Tier-0）：当日价 <= `stop_loss_price` → `stop_loss_sell`，全部清仓。
3. 趋势卖出许可（分态，v1.19）：趋势态 收盘 < MA60 或 < MA120（标注 60 日/120 日档）；反转/筑底态 收盘 < 启动结构锚（结构档）或 < MA20（短期档）→ `trend_sell_allowed`，解锁减仓乃至清仓权限，非自动卖出。
4. 估值卖出资格：现档为较高估/高估 → `valuation_sell_eligible`，给出可卖金额 = max(0, 持仓市值 − `build_amount_cny`)（留底原则）；现档中性及以下无此状态。
5. 其余一律 → `hold`（无浮盈档位约束）。

风险预警（仅提示，不直接触发卖出）：

1. 总仓位越出 100-160%N 包络 → 提示（阈值唯一见 §13）。**结构占比与单票权重按 §13 第 8 条的主动口径处理：被动上涨造成的越限不在本条预警之列**（个人体系 §2.1/§4.1 同步）。
2. 账户自峰值回撤 -8% / -12% / -20% → 去杠杆 / 黄色警告 / 红色警告（与个人投资体系 §13.1 同步；脚本读取账户快照计算）。
3. 未构成大趋势走坏的技术走弱信号（高位放量滞涨、缩量阴跌等）→ 风险提示，不直接卖出。
4. **（v1.21 退役）单笔风险的持仓监控版**——原"持仓市值 × 当前止损距离 ÷ 净资产 > 1.5% → 风险提示"已撤销，不再输出任何预警。该指标 = 持股数 ×（现价 − 割肉价）÷ 净资产，在股数与割肉价固定时是**现价的单调增函数**：只可能因股价上涨而触发，股价下跌反而使其收敛。它度量的是"浮盈回吐空间"，不是本金损失风险——与 v1.20 已撤销的组合级止损网格 Σ(仓位%N×止损距离) 是同一构造的逐票版本，撤销理由与个人体系 §17.4 归档的用户原述一致（"持有的股票大幅上涨了，反而由于止损价没有变化而风险增加，这是很荒谬的"）。**保留不变**：§13 第 6 条的**建仓时**单笔风险校验（建仓金额 × 止损距离 ≤ 1.5%N，对应个人体系 §13.2"战术和右侧新开仓必须满足"）仍是买入前置硬条件；逐票 Tier-0 割肉价与账户回撤梯 -8%/-12%/-20% 不受影响。脚本继续在 `daily_holdings_actions.csv` 输出 `single_trade_risk_pct` 作为审计字段，但不再置 `over_limit` 标记，扫描日志不再据此标黄。
5. 持仓估值档位恶化：对照最新核心池，档位降为高估/无法估值或已出池 → 提示复核（结合估值卖出许可处理）。

### 大模型判定的卖出与风险信号

硬证伪离场（判定成立即 `forced_exit`，立即清仓）：四类清单见「卖出许可」第 2 类，不再重复；第④类结构性 thesis 证伪必须以公告/监管文书/多个权威信源核实为准。

以下信号自 v1.12 起不构成独立卖出通道，一律作为风险预警与复核输入：

1. thesis 走弱（未坐实）：订单延迟未取消、客户验证进度落后、毛利未如期改善、竞争加剧、技术路线或政策逻辑边际变化、管理层口径与披露数据出现张力——坐实即升级硬证伪。
2. 估值过热：当前价已反映 bull case、未来 2-3 年利润已被定价、股价远快于盈利上修——是否可卖以 §6.2.1.6 现档（较高估/高估）为准，见「卖出许可」第 3 类。
3. 催化剂对照：对照买入时的催化剂地图（§10.1 第 10 条），已兑现的按催化兑现重估；超期未兑现的作为时间维度走弱信号。连同机会成本变化，作为风险预警与观察调整的参考。

| `valuation_sell_eligible` | 现档较高估/高估，允许卖出建仓金额以上的增值部分（留底原则） |
| `trend_sell_allowed` | 大趋势走坏（收盘跌破 MA60/MA120），允许减仓乃至清仓 |
| `risk_alert` | 出现暴露超限、回撤预算或治理/财务风险，需复核 |

### 卖出前人工核对

任何 `stop_loss_sell`、`forced_exit`、`valuation_sell_eligible`、`trend_sell_allowed` 的实际执行前必须核对：

1. 当日是否有澄清公告或被误读的利空（含触发所依据的数据是否有误）。
2. 是否处于不可交易状态（停牌、一字跌停）。
3. **仅对估值卖出与趋势卖出**：触发是否为单日噪声（刚好贴线/贴带顶），可等待 1-3 个交易日确认；`stop_loss_sell` 与 `forced_exit` 不适用本条，核对仅限第 1、2 项，通过即当日/次日执行，不得延迟。
4. 估值卖出的留底核对：卖出后剩余持仓市值原则上 >= `build_amount_cny`（趋势卖出与降风险方向卖出不受此限）。
5. 卖出后若反向走强的再买回条件。
6. 执行后按 §10.3 回写持仓清单并记 `execution_record`。

### 与买入侧的衔接

1. 阶段四产生 `buy_candidate` 并实际建仓后，必须把该持仓写入 `a_share_holdings.csv`，记录策略标签、`build_amount_cny`、`initial_shares`、`cost_basis`、`stop_loss_price`、突破平台价、bear case与退出条件。
2. `a_share_holdings.csv` 与买入候选相互独立：买入候选是池内信号，持仓清单是已建仓事实。
3. 每个持仓动作结论写入决策日志，`workflow_stage = holdings_sell_scan` 或 `manual_sell_check`。

## 15. 执行方式

本文件是A股选股、估值、量价扫描的主执行规范。后续可以用类似以下指令执行固定流程：

```text
请基于 docs/000_Ashare_workflow.md 执行今天的A股每日量价扫描，并将结果写入固定输出文件和结论日志。
```

执行分工：

1. 能由脚本稳定完成的部分必须用脚本执行，例如证券名单更新、队列生成、核心估值合格池物化、每日量价指标扫描、每日持仓技术与风险触发扫描和历史回放。
2. 需要判断业务质量、护城河、估值模型、研报假设、公告真实性和用户defence的部分，由大模型按本文件中的执行规则和输出字段执行。
3. 大模型执行时不得临时改标准；如发现标准不合理，先修改本文件，再按新版本重新执行。
4. 每个产生结论的脚本输出和每个大模型批次结论都必须写入 `data/processed/a_share_workflow_decision_log.csv`；队列生成脚本只做调度，不单独写结论日志。
5. 每日量价扫描不是买入命令。买入必须满足 §10.1 **要素项 7 项**（硬前置，任一不达标不得建仓）；研究档案项为限期义务、不阻断建仓但未补齐期间禁止加仓（§10.4，v1.24）。成交后按 §10.3 回写，并按 §10.4 第 2 条判定 `approved`/`compliant`/`off_system`。
6. 每日持仓卖出扫描不是卖出命令。无条件清仓只由割肉价（Tier-0）与硬证伪（`forced_exit`）决定；估值卖出（现档较高估/高估，留底原则）与趋势卖出（§14 分态口径：趋势态破 MA60/MA120，反转态破启动结构或 MA20）为许可而非指令，均须完成阶段五（§14）的卖出前人工核对后执行并回写。
7. **执行时点不设限（v1.23，2026-07-30 用户决定；原「买入时间窗」14:40 规则撤销）**：买入与卖出**均无时点约束**，任一交易时段均可执行。原 v28/v29 的买入时间窗（新建仓/加仓仅允许 14:40 之后）自本版撤销——理由见用户原述与 §17.6 评估：该窗**约束力与可执行性都不成立**（成交时间戳不进入本流程输入，代理无法核验，实际只能产出"时间窗未核"这类不可证伪的缺项，不构成任何真实拦截），而其本意"避免以未定型的日内 bar 为决策依据"已由三处现行机制独立承担：§9.1 第 4 条（盘中判定一律标注"待收盘定型"）、§8.13 执行规则 5（有效段位取近 5 个交易日最高段，单日日内读数不决定段位；失效归零另需放量下跌或破触发日最低价）、§10.1 第 13/14 项（当日公告核对 + §8.8 过度延伸过滤）。

   撤销范围**仅限时点**，买入的全部资格前置一项不减：§6.2.1 分层×估值矩阵、§8.13 入场阶段、§10.1 闸门全 15 项、§13 第 6 条建仓时单笔风险 ≤1.5%N、§7.5 复核冻结、§11 风险过滤、§13.4 包络与 §13.7 棘轮，均原样有效。卖出侧本就不受时点约束，口径不变：Tier-0 割肉价触及与 Tier-1 硬证伪按 §14 触及即执行、不得延迟；其余主动卖出任意时点可执行，降风险方向不设时间障碍。扫描报告不再输出"14:40 后执行"标注，也不再把时间窗列为 off_system 缺项。

   **残留暴露与对价（§12.6 第 5 组跟踪）**：撤销后，以盘中未定型读数追价买入在规则层面不再受阻，唯一约束是上述资格前置与执行者自律。为对称建立证据义务，§12.6 新增第 5 组对照样本，逐笔记录买入的成交时段（用户回报时提供即记，不强制）与其后 5/20 日前向收益；若盘中时段买入的表现系统性劣于尾盘时段，回补时点约束。
