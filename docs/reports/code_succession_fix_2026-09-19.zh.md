# 换码主体的除权事件与面板双代码缺口修复（OI-192，2026-09-19）

本周报告审核发现：深赤湾A `000022` 在事件表中零行，其全部分红送转挂在后继代码 `001872` 招商港口名下；同时 `001872` 自 2009-04-30 起在历史面板在册，与 `000022` 同价并存。本次按轨道 A 修复数据与装配机制，重建 `000022` 逐日状态，并以修复前后输入对 `BASE` 做 14 起点护栏对照后重登。规则落点见工作流 §8.3，回测日志 §12.250。

## 修复

1. **参考表与唯一实现**：`data/reference/a_share_code_succession.csv` 登记 (旧码, 新码, 旧码末个交易日, 新码首个交易日)；`scripts/code_succession.py` 承担两条派生规则。事件取数 `fetch_ohlcv_history.flush_actions` 每次落盘前把新码名下不晚于旧码末日的事件复制到旧码（旧码已有行不覆盖、预案行不复制）；面板装配 `build_moat_panel.py` 校验旧码区间不晚于旧码末日、新码区间不早于新码首日，违反即失败。单元测试 `test_code_succession.py`（7 项）与 `test_build_moat_panel.py` 新增冲突用例。
2. **事件表**：离线补写 25 行 `000022` 事件，与 `001872` 2018-12-20 前的行逐条一致；其余行不变。
3. **判定源**：`verdicts_pit_moat_v6.csv` 增 `001872` 除名行（主体判定由 `000022` 承载；新码启用时主体已于 2015 年退出，未另行判定）。重装配后 v6b 只少 `001872` 的 79 行，其余 9,965 行逐字节不变；`--check-panel` 通过。
4. **逐日状态**：按 §6.7 第 2／2b 步命令以 `--codes 000022` 重建两侧带与状态（各约 12 秒），拼回 `roic_daily_raw(_b2)`、`roic_bands(_b2)`、`a_share_daily_states_adopted/b2`，非 `000022` 行哈希不变；再按第 3 步合成持仓侧。建带器 2026-09-10 前后版本对 `000022` 输出逐位相同。
