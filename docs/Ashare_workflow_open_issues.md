## OI-016 A-1/A-2 背离时的卖出抑制规则只存在于代码注释

- **发现日**：2026-08-02
- **触发**：核实美的集团当前状态是否正确
- **涉及章节**：§6.5.3（未成文）、池物化 `build_a_share_core_valuation_pool.py`
- **状态**：待修订

v1.41 在 `scripts/build_valuation_band_cards.py:885` 写下：「两法背离 >25% 时**不得据较低的那条发卖出提醒**——A-2 是相对法、有『看不见系统性错价』的构造性盲区，A-1 是绝对法、有参数敏感性，二者失效方式不同。取孰低对买入侧是保守的（正确），但反过来当『贵』的证据不成立。同下限带与周期假设未决的处置。」

该规则**只存在于这条注释里**：`docs/000_Ashare_workflow.md` 全文无「背离不发卖出提醒」的成文条款；池物化只对 `band_is_floor` 与 `cycle_assumption == mean_reversion_assumed` 两种情形把 `trim_alert` 降为 `holdable`，`band_fragile` 在 `build_a_share_core_valuation_pool.py` 与 `scan_holdings_sell_signals.py` 中**一次都没有出现**。注释里的「同下限带与周期假设未决的处置」描述的是一件没有发生的事。

判例：美的集团（000333）背离 **47%**（A-1 中值 102.7 vs A-2 中值 70.07），`band_fragile=true`、`implied_return_tier=较低估`（两阶段 DCF 每股 108.1、现价反解隐含折现率 r≈9.8%），而 A-2 相对法带 62.69-77.44 对现价 87.60 判较高估。全池 22 个 A-1/A-2 背离行中，**它是唯一落在 `trim_alert` 的一行**——即该规则若实现，唯一会改变的就是这一行。2026-08-01 扫描据此发出减仓梯 H 台阶提醒（减剩余股数 20%，约 5.26 万），而它正是 v1.41 声明不成立的那个读法。

附带发现（同一行内，一并登记）：`cycle_note` 把 **A-1 Gordon 带中值 102.7 标注为「DCF 每股」**，而同行 `band_sensitivity` 里真正的两阶段 DCF 值是 108.1——同一字段名指了两个不同的量。另 §6.5.4 正文与 v1.40/v1.41 版本记录仍写着 v1.40 的旧数（每股 144.1、r≈10.5%、带 62.81-77.59），v1.41 改 r=8.5% 后未同步。

## OI-015 下限带的锚可以滞后于已披露的业绩预告，运行率硬校验按构造抓不到

- **发现日**：2026-08-02
- **触发**：核实高德红外合理价区间 2.721-3.326 何以严重偏离现价 12.61
- **涉及章节**：§6.5.4（运行率硬校验、D 兜底口径）、§6.5.6、池 MD 渲染
- **状态**：待修订

三层问题，由外到内：

**① 运行率硬校验读不到预告。** §6.5.4 的「峰值/中枢盈利输入不得低于最近一个已披露季度的年化运行率」在 `build_valuation_band_cards.py:1209` 实现为 `run_rate = ttm(periods, "PARENTNETPROFIT")`——只读**已披露财报期数**，`performance_predicts` / `performance_express` 从不入参。判例高德红外：锚为 2026Q1 口径 TTM 扣非 **9.04 亿**，对 TTM 归母 9.69 亿之比 0.93，高于 0.85 阈值故不触发；但 7/9 预告的 H1'26 扣非已达 **12.35-14.15 亿**（单个半年即超全部 TTM），滚入后 TTM 扣非为 **17.0-18.8 亿**，锚/运行率实为 **0.48-0.53**，远在阈值之下。按预告滚动后的下限带约 5.12-6.92（现空间由 −76% 收窄到约 −52%）。**一个已经结束的报告期的预告是已兑现盈利，不是成长预期**——D 兜底「base 带只按已兑现盈利」的本意不排除它，§7.5.5 express 复核机制本身就以预告为输入。该行的 `估值事件` 写的正是「业绩预告」、`valuation_reason` 通篇引用该预告，唯独带的算术没用上它。

**② §6.5.6 成长期权从未执行过一次。** 全池 261 行 `growth_option_value` **全为空**。它是 §6.5.4 指定用来把下限带抬到完整价值的唯一机制（高德红外的 `upgrade_path` 也点名了它），成文未落地，故 88 个下限带全部停在下限——与 OI-002 记录的「§6.5.4 运行率条款实现 0 次」是同一种病。

**③ 展示层把下限当公允中枢。** 全池 **88 行** `band_is_floor=true`，其中 **71 行**显示为「高估」（最差 −90%）。池物化已按 §6.5.5.1 把这些行的 `trim_alert` 降为 `holdable`（不发卖出提醒，正确），但池 MD 既不显示 `band_is_floor` 也不显示 `anchor_quality`，且表头把「空间」定义为「区间中值（**模型认可的公允中枢**）相对现价的涨跌幅」——对下限带这句话不成立。§6.5.4 明写「其档位偏保守是已知的、不构成『贵』的证据」，而用户直接阅读的文件里没有任何一处标出这件事。

附带（不单独立项）：该行 `valuation_reason` 结论写「定较低估」，与机械定档的「高估」并存且无标注——v1.28 分工恒等式之后，建带卡的人工结论文本未随定档规则改写。
