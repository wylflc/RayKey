# 逐票研究目录（§6.5.7）

每个**值得研究的公司**一个目录：`data/companies/<代码>_<名称>/`

```
data/companies/<代码>_<名称>/
├── README.md            # 主分析文档＝估值档案正文（人读；带、方法、推导、跟踪指标、复核触发）
├── research_ledger.md   # 研报跟踪台账（§6.6.1，逐份研报一行，一致预期取中位数）
└── sources/             # 下载的原件：定期报告、业绩预告/快报、券商研报、交易所公告、行业数据
    └── INDEX.md         # 来源清单：文件名/类型/期间/来源/抓取日/用途
```

**为什么用目录而不是散文件**：同一家公司的分析文档、研报台账与原始材料此前分散在
`data/processed/analyst_reports/`（台账）与各处，复核时反复重新下载同一份年报或研报。
合并为一个目录后，**材料下载一次即长期留存**，后续复核只做增量。

**与 CSV 的分工**：`data/processed/a_share_valuation_dossiers.csv` 是**机器可读的唯一真值来源**
（建带引擎 `build_valuation_band_cards.py` 只读它）；本目录是人读的正文与证据侧。
两者必须一致，CSV 的 `dossier_dir` 列指向对应目录。

**建目录的门槛**（§6.5.7）：①已建估值档案的公司；②已建研报跟踪台账的公司；
③用户点名需要长期跟踪的公司。不满足者不建目录——目录本身是维护义务，不是收藏夹。
